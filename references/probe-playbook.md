# 挑刺清单（探针模板库与方法库）

定位：让对抗探针**有单可循**，不靠临场发挥。A 节把既有业务坑点库与缺陷模式库映射为可机械套用的探针模板（坑点→探针），B 节是通用测试方法库（方法→何时用/怎么用/典型失效）。本清单是**可选武器库**：构造探针时可查本清单，也可基于 `ATK-` 攻击假设或现场观察自主设计——**清单未覆盖的攻击场景与清单内探针具有同等执行优先级**，清单已覆盖 ≠ 攻击面已覆盖。按 `adversarial-testing.md` 补【输入/扰动】与【预期依据】两段；判据登记与风险面关联见 `oracle-contract.md`。

## A 节：坑点→探针模板

每条模板：探针模式（【输入/扰动】骨架）、典型判据来源（登记 ORC 时从需求/契约/不变量落实，模板只提示方向）、典型失效（关联 `skills/case-generator/references/methodology/defect_patterns.md` 的模式类别）。坑点原文见 `references/business-pitfalls.md`，可按模块查库，识别到的风险按下表展开成 ADV 义务；未列入本表的风险同样可以自主构造探针。

| # | 模块 | 探针模式（输入/扰动骨架） | 判据方向 | 典型失效 |
|---|---|---|---|---|
| P1 | 登录与会话 | 连续失败锁定期内换入口重试；会话过期后直接调原接口 | 需求的锁定/过期策略 | 会话残留（模式 4） |
| P2 | 权限与数据边界 | 低权角色直连 URL/接口；遍历/替换他人资源 ID | 权限矩阵（invariant） | 越权读写（模式 4） |
| P3 | 表单与提交 | 双击/回车/刷新重提；校验失败后检查输入保留 | 契约的幂等与校验规则 | 重复记录/丢输入（模式 1/2） |
| P4 | 上传下载 | 改扩展名+MIME 双变体；`../` 与超长文件名；直连他人下载链接 | 契约的上传校验与归属规则 | 恶意文件/越权下载（模式 2/4） |
| P5 | 支付交易 | 同一回调重放两次；金额 0.01/整数边界/优惠叠加 | 契约的幂等键与金额规则 | 重复入账/精度错误（模式 2） |
| P6 | 导入导出 | 5 行含 1 行非法的混合文件；10 万行量级 | 契约的部分失败语义 | 半成品入库/静默截断（模式 2） |
| P7 | 异步回调 | 回调先于任务完成到达；重复回调；畸形 payload | 契约的状态机与回调契约 | 状态残留/错序（模式 3） |
| P8 | 接口契约 | 类型污染（数字传字符串、数组传对象）；畸形 JSON/截断报文 | 接口契约（contract） | 500 或静默丢包（模式 10） |
| P9 | 兼容设备 | 目标浏览器最低支持版本实测关键旅程 | 产品支持范围声明 | 功能不可用（模式 8） |
| P10 | 弱网 | 断连后重试；慢响应下重复提交 | 需求的重试/超时规则 | 重复写入/死等（模式 2/3） |
| P11 | 安全基线 | 已登出会话重访受保护页；JWT 改签名位 | 安全规则（不做攻击，仅防护验证） | 会话未失效（模式 4） |
| P12 | 可访问性 | 纯键盘走完整旅程含弹层开闭 | 无障碍基础规则（a11y-audit.md） | 焦点陷阱（模式 6） |
| P13 | 国际化 | 全角/零宽/RTL/组合字符入各文本字段 | 需求的字符集规则 | 乱码/截断（模式 2） |
| P14 | 时间时区 | 跨天时刻提交；夏令时/时区偏移下的截止判断 | 需求的时区与截止规则 | 边界错日（模式 2） |
| P15 | AI 生成 | 同输入重放 3 次比对稳定性；固定判据（必须包含/不得出现）核对输出 | 预先冻结的可执行判据 | 规则性幻觉（按高严重性） |
| P16 | 文案 | 逐页扫未渲染变量（`{{}}`/`null`/`undefined`）；同一对象在不同页面对比叫法；点按钮核对结果与按钮字面是否一致；故意触发错误看提示是否定位到字段 | `content` 属性面（visual-usability.md 文案检查面） | 误导/未渲染/术语冲突（模式 7） |
| P17 | 布局 | 超长文本（200 字/长英文串/长数字）灌入每个容器；0 条与 1000 条两端数据；320px 与 200% 缩放；打开弹层看遮挡与滚动 | 无基线也可判：遮挡、溢出、错位、撑破属客观异常 | 遮挡/溢出/错位（模式 5） |
| P18 | 操作逻辑 | 慢网下连点提交；提交后立刻刷新；危险操作找撤销；标必填与真正拦截的字段做差集 | 需求/契约的幂等、防重、确认规则 | 重复写入/无反馈/无兜底（模式 6） |
| P19 | 数据一致性 | 改完立刻：列表/详情/导出/统计四处取值比对；新标签页与新会话再取一次；跨角色取一次 | 持久化数据为唯一裁决方，界面须提示不一致 | 陈旧值/静默分叉（模式 9） |
| P20 | 可量化界面 | 页面内取 `background_source` + 实测算对比度、量目标尺寸并排 2.5.8 例外、注入间距覆盖做前后差分、量 320px 溢出；交 `ui_measure.js` → `ui_metrics.py` | WCAG 2.2 1.4.3/1.4.11/1.4.12/1.4.10/2.5.8 | 对比度不足/目标过小/间距覆盖丢内容/重排破损（模式 5/6） |
| P21 | 状态组合 | 按 角色×状态×数据条件 展开格点，挑"最不可能被手工想到"的格点执行，把未覆盖格点摊出来（`state_matrix.py`） | 状态迁移规则 + 业务不变量 | 状态机规避、跨状态数据残留、越权后状态不一致 |
| P22 | 控件遍历 | 清点全部可交互控件，逐个点/聚焦/悬停并记录反馈；"无反应"记为线索非缺陷（`control_traversal.py`） | 任务可完成性 + 反馈一致性 | 死按钮、点了没反应、禁用态可点、重复提交无防护 |
| P23 | 文案一致性 | 抽取全部可见字符串，比对术语表、同角色近义异写、未替换占位符、失败态里的成功字样（`copy_consistency.py`） | 术语表 / 需求文案 | 术语不一致、提示误导、模板变量残留 |
| P24 | 断言杀伤 | 对支撑结论的断言抽样注入已知故障，验证断言会失败；抽样由哈希决定不由人挑（`assertion_mutation.py`） | 断言应捕获的故障类型 | 假绿——断言不会响，跑再多都是绿的 |

模板是骨架不是终点：套用后必须补齐该需求场景下的具体判据（ORC），无来源判据只能出观察，不得出 PASS/FAIL。

## B 节：通用测试方法库

| 方法 | 何时用 | 怎么用 | 典型失效 |
|---|---|---|---|
| 等价类 | 字段有明确取值域 | 有效/无效类各取 1 代表，无效类必须实际提交 | 只测有效类，无效类漏拒 |
| 边界值 | 有数值/长度/数量限制 | min-1、min、max、max+1、0、空 | 只测域内不测域外 |
| 判定表 | 多条件组合决定行为 | 条件全组合降级化简，每列一用例 | 只走主路径组合 |
| 状态迁移 | 对象有明确状态机 | 合法迁移全覆盖 + 非法跳转逐一尝试 | 只测合法迁移 |
| 组合/正交 | 多参数交互 suspected | 正交表覆盖两两交互，高风险三维全组合 | 参数孤立各测不测交互 |
| 差分/孪生 | 存在两个应一致的视图（列表 vs 详情、API vs UI） | 同数据双通道读回比对 | 单通道自证 |
| Metamorphic | 无独立 oracle 但有不变关系 | 同语义输入变体（改序/改编码/重复），关系输出应不变 | 变体间不一致未察觉 |
| 故障注入 | 有依赖可扰动（授权+隔离） | 按 assertion-challenges.md B 节成对采集，注入/自然分账 | 注入结果冒充产品缺陷 |
| 并发/时序 | 共享资源多入口 | 双会话竞争同资源；A 进行中插入 B | 竞态只测单线程 |
| 回滚补偿 | 事务有多步 | 中途断失败，核对半完成状态与补偿 | 半完成状态残留 |
| 视觉走查 (`visual_walkthrough`) | 有页面且要看样式/布局 | 逐状态截图 + 元素几何与命中测试互证；超长文本、空满两端、窄屏、缩放各看一次 | 只看首屏、只看默认态 |
| 文案核对 (`copy_audit`) | 有面向用户的文本 | 逐页对照术语表/按钮语义/提示语；扫未渲染变量；触发错误看定位 | 只读主流程文案，不看错误与空态 |
| 启发式任务评审 (`heuristic_review`) | 要评估操作逻辑是否反直觉 | 以具体用户目标走完任务，记录绕路步骤、重复输入、缺失反馈与不可撤销点 | 把个人偏好当缺陷 |
| 三通道对账 (`consistency_check`) | 有持久化与多个展示入口 | 前端展示 / 接口响应 / 缓存副本各取一次，比对后再判 | 单通道自证 |
| 影响面回归 (`regression_impact`) | 本次有变更 | 变更点 → 依赖 → 旅程 → 用例逐级列出，未选写明理由 | 只回归改动页面本身 |

方法选择记入 ADV 义务的 method 与 probe_type（枚举见 `schemas/adversarial-plan.schema.json`，与 `scripts/adversarial_data.py` 的 METHOD_IDS 同源）与预算；每方法的发现走统一候选流程（`finding-triage.md`），不因"方法常规"而跳过候选复核。

## C 节：对抗场景设计（纵向组合）

A 节模板与 B 节方法都是**横切维度**：回答"单点打什么、用什么手法打"。但目标是"更全面的场景设计"——真正难发现的缺陷往往不在单点，而在**序列与组合**里。本节要求对抗批次除单点探针外，显式登记**对抗场景**（`SCN-ADV-`，形态见 `schemas/adversarial-scenarios.schema.json`），回答"怎么串起来打"。

三类必查场景（每类要么登记实例，要么写明不适用理由，不得静默缺省）：

| 类型 | 设计要点 | 示例 |
|---|---|---|
| `cross_module` 跨模块组合 | 取两个及以上 SURF 的交互点，设计"单看各自都对、组合起来坏"的序列；至少关联两条 SURF | 权限切换 × 异步回调（切角色期间的回调写入了旧角色的数据） |
| `operation_sequence` 操作序列反常 | 不看单步输入是否合法，而是**整段序列反常**：先建后删再恢复、连续快速切换角色、绕开入口直达深层页后回退 | 新建草稿→删除→恢复→立即编辑，校验是否读到已删快照 |
| `state_bypass` 状态机规避链 | 沿状态机找**非法迁移链**（非单次非法跳转，而是多步合法操作拼出非法状态） | 审批中→撤回→改内容→重新提交，是否绕过原审批人 |

设计纪律：

- 场景的 `sequence` 至少两步，**不得退化为单点输入**（单点属 A 节模板范畴）；
- 场景必须有 `expected_basis`（预期依据来源），否则只能产出观察，不能判 PASS/FAIL；
- 场景通过 `obligation_refs` 关联到承载它的 ADV 探针——**场景不直接等于缺陷**，仍走 `finding-triage.md` 候选流程；
- 组合类缺陷常与单点缺陷**不同根因**，不得因单点已测就跳过组合场景（参考 `finding-triage.md` 的"同文案不同原因不合并"）。

**机械校验（不是自觉）**：场景文件经 `scripts/adversarial_data.py --scenarios <文件>` 校验，强制 `sequence ≥ 2` 步、`cross_module` 至少关联两条 SURF、ID 以 `SCN-ADV-` 开头；`scenario_gaps()` 把"零场景""缺跨模块组合""高风险面未被任何场景覆盖"列为覆盖缺口，并由 `adversarial_gate.py --scenarios` 压入结论上限——**不登记场景，结论最高只能到"待核实"**。

## 使用纪律

- 本清单是**提示性全集**，不是逐条必跑：按风险面（SURF）挑适用模板，未选的写明理由；
- A/B 节管**单点**（模板 + 方法），C 节管**组合与序列**（对抗场景）；两类都要过，只做单点会漏掉组合型缺陷；
- 模板与 `references/business-pitfalls.md` 的"先看什么"列联动：坑点库判风险，本库给探针骨架，`skills/case-generator/references/methodology/defect_patterns.md` 给失效归类；
- 新坑点/新模式沉淀时同步回填本清单（两处改一处的，在 SYNC-NOTES 登记原因）。
