# 界面样式、交互易用性与基础无障碍

## 入口与判据

每次网站测试都评估这三类是否适用，实际执行具备条件的检查，不把它们留成报告里的三个标题。它们与功能、性能共用需求、场景、用例、运行和缺陷标识。小任务沿用同一清单；复杂任务按页面/组件、角色、视口、状态分批检查，不强制全笛卡尔组合。

- **界面样式**：是否看得清、显示完整、布局正确；有设计稿、原型、设计令牌或确认旧版时记录其版本后对照。没有基线仍可查实际遮挡、横溢出、截断导致信息缺失、图片损坏/变形、明显错位和布局位移，不宣称像素一致或品牌审美达标。
- **交互易用性**：按具体用户目标检查入口、理解、反馈、纠错与完成成本。基于常用体验原则的检查是专家启发式评审，不是已组织真实用户研究；未经观测不报告用户满意度、总体成功率或“所有用户都觉得难用”。
- **基础无障碍**：实际使用键盘，检查名称、标签、焦点、非仅颜色提示等。自动规则和一次键盘检查不等于完整 WCAG 认证或屏幕阅读器实测。需要覆盖键盘全流程、读屏播报、缩放重排、动效与状态提示时，按 `references/a11y-audit.md` 执行并逐条标注已验/未验。

每个发现标为“有依据的实现缺陷 / 可观察的客观异常 / 待确认需求问题 / 体验建议 / 检测候选待复核”。缺陷须有可重复现象、实际影响及依据；主观建议不混入已证实 BUG 数。通过标准不使用个人喜欢的字体、颜色、圆角或宣传页审美分数。文本省略、内部横向滚动和响应式换行可能是合法设计，先核对是否影响任务及可访问完整内容。

## 结论红线（借鉴 figma-ui-parity；无设计稿时尤须遵守）

- 没有设计稿基准时，报告标题与结论**不得写“还原度”**，只做页面 UI 走查。
- **不得声称“像素级通过”**：像素级结论只能来自真实像素比对能力（如 visual-parity），截图+样式核对只能标注“部分验证”。
- **不得声称“通过 WCAG AA”**：内置无障碍规则是 WCAG 的子集，更全覆盖需全量审计工具（如 `--axe`）；已按 `references/a11y-audit.md` 人工实测的，只按条列“已验/未验/不通过”，结论仍不得写“通过 AA”。
- 未经确认的临时基线只作参考，不得作为回归通过依据。

## 界面样式检查顺序

1. 核对当前URL、实际页面、角色、视口及内容非空，避免登录页、错误页或空白页被当成目标页通过。
2. 记录默认、加载、空、错误、成功、禁用、权限态的适用性；打开实际存在的弹窗、抽屉、菜单、页签，必要时触发长文本、校验失败、大数据和缩放。只滚到页面底部不等于这些状态已检查。
3. 在已确认支持的桌面/窄屏或其他环境逐状态观察；截图与元素几何、滚动和命中测试相互佐证。检查可见区域和屏外可滚动内容，不只查首屏。
4. 检查遮挡/重叠、重要文本缺失、按钮出视口、布局抖动、粘性页脚覆盖、图片失效及比例、字体加载后变化；图片/渐变上的文字需实际看截图，不靠简单纯色对比度算法代替。观察器的中心点遮挡抽样与object-fit比例检查只作为线索，边缘遮挡、动画过程、富媒体与固定浮层需实际截图和操作确认。
5. 有基线才做差异比较。记录浏览器、字体、视口、主题、数据、动画状态和动态区域掩码；掩码须有理由并另检查被屏蔽业务，不能归一掉整页真实偏移来消除假阳性。
6. 关键状态截图交给独立视角复核时，先提供截图、任务和已确认标准，不灌输实现理由；其意见再回到实际页面验证，不能让评审者审美偏好直接生成缺陷。

## 用户体验易用性任务检查

| 维度 | 实际执行动作 | 记录与边界 |
|---|---|---|
| 入口可发现性 | 从用户正常入口寻找主要操作，核对名称、层级、当前位置和下一步 | 记录实际路径及找不到的操作，不凭熟悉后台直达地址代替首次用户流程 |
| 一致性与理解负担 | 对照同类按钮、标签、字段单位、导航和状态术语；按任务理解提示 | 违反已确认术语是缺陷；仅更喜欢另一种说法属于建议 |
| 状态可见与反馈 | 保存、上传、筛选、生成后观察处理中/成功/失败、禁用和重复点击反馈 | 提示出现不等于业务完成；核对业务读回及等待终点 |
| 错误预防 | 尝试空/非法/重复数据、误点取消、危险操作的安全确认 | 只使用安全数据和已授权操作；不为测试确认弹窗而删除真实数据 |
| 错误解释与恢复 | 触发可控错误，按提示修改、重试或返回，检查输入是否保留、错误定位是否具体 | 未授权故障注入不执行；错误恢复不得隐性重复写入 |
| 用户控制 | 返回、刷新、关闭再开、撤销及中断，检查状态与未保存内容处理 | 是否需要确认或保留以需求为准；未定义则列需求/体验问题 |
| 任务效率 | 完成关键任务，记录绕路、重复输入、多余步骤与高频任务阻碍 | 真实步骤数可报告；不凭代理速度推断人类耗时或整体完成率 |
| 触摸与响应式 | 真实或明确模拟的小屏查看可点击性、固定区域、键盘弹出后的操作；同时核对文档是否声明`width=device-width`，缺失时移动端会按默认布局视口渲染再整体缩放 | 不强制套用固定按钮像素阈值；视口模拟不等于真机 |
| 数据信任 | 核对保存、同步、导出、删除反馈和当前数据一致，不出现相互矛盾状态 | 没有内部观测时限定黑盒结论；敏感信息不能写入证据 |

**文案检查面（content 必选属性，v3 G16）**：逐页核对术语一致性、单位/精度、数字/日期/时区格式、状态术语、按钮语义（动作与结果一致）、错误提示是否定位到具体字段并给出恢复路径、模板变量是否残留未渲染（如 `{{name}}`、`null`、`undefined`）、长文/小屏是否截断、i18n 是否串行。客观错误（术语冲突、未渲染变量、错误定位缺失）记为缺陷；主观偏好记为建议，二者分账。检查面以 `content` 属性登记到探索清单，被阻塞/未执行时结论上限为待核实，不得由 functional 视角一条 PASS 清空。

## 基础无障碍实际检查

- 从页面入口用 Tab / Shift+Tab / Enter / Space / Escape 检查适用控件；不只检查存在 `tabindex`。
- 焦点应可见且顺序合理，弹窗开启、关闭时检查焦点去向；背景是否能误操作、是否困在无出口区域需实际验证。
- 表单有可辨标签，错误能关联到对应输入；按钮/链接能说明用途。空名称候选需要结合图标、ARIA、标题及实际辅助树复核。
- 信息不只通过颜色传递；重要图片有适当替代信息。装饰图片与隐藏重复内容不要机械判缺陷。
- 产品要求对比度或辅助技术时核对标准来源并使用实际工具；工具缺失列缺口，不能用所有元素“看起来清楚”宣称合规。
- 适用时检查减少动态效果、触摸/鼠标差异；需求未约定的动画偏好作为建议，不把无动画或固定布局自动判错。

## 浏览器观察器与性能边界

可使用本包 `scripts/browser_observer.js` 收集有限的页面、视口、视觉/名称/遮挡/比例候选及可得性能覆盖，并用 `scripts/observation_bridge.py` 转成待复核条目。调用方式和数据边界见 `exploration-runtime.md`；纯逻辑测试为 `tests/test_browser_observer.js`，桥接测试为 `tests/test_observation_bridge.py`。它不代替真实截图、键盘操作、设计对照、用户任务和问题复现，不直接返回完整业务验收通过，不发送网络请求或修改业务数据。截图先落盘归档：宿主只允许写受控目录时，写入后复制到证据目录并核对文件大小与SHA-256；所有写盘都被拒绝才按 `exploration-runtime.md` 的降级取证方式执行，观察中标注“截图未归档”。

页面性能分加载、主要内容、布局偏移、关键交互和资源/长任务分别检查。观察器只给导航、资源、FCP、LCP的覆盖状态，交互(INP)、布局(CLS)与长任务固定为未采集，须用当次会话提供的性能追踪能力补齐：加载型开录后刷新取LCP与CLS，交互型不刷新直接开录并真实操作控件取INP，原始追踪文件落盘归档。多条件验证按 `exploration-runtime.md` 的条件劣化矩阵组织（视口×网络×CPU×冷热），每格保留追踪文件与哈希，阈值须写明出处，用 `scripts/perf_matrix.py` 汇总为CSV；单格达标不得写成整页性能达标。记录设备、浏览器、网络、数据量、冷暖缓存、样本数和阈值来源。导航与资源时间不等于真实用户分布；未采到 INP、LCP、CLS 等时保持未知而非0；没有有效交互不能宣称交互性能达标；合成点击不算交互样本。负载、容量和故障恢复见方法论，须对应授权。

## 独立视图与交付

用户可分别查看“界面样式”“交互易用性”“基础无障碍”，并保留关联功能/性能/恢复视角。默认交付 CSV（UTF-8-sig、逗号分隔、含逗号换行引号字段正确转义）；截图为实际附件路径，不为凑报告伪造画面。视图是同一事实按属性筛选，不重复计算总体测试数或 BUG 数。

每项列：记录ID、页面/组件、角色、视口/设备、触发状态、实际任务/动作、判据来源、观察、问题类型、影响、证据、建议、复测标准、执行状态及缺口。`exploration_state.py` 的 CSV 提供基础执行/候选视角；问题类型、严重度和业务判定由专家核对并链接现有缺陷记录，不冒称该脚本已自动完成UX评级或用户研究。输出细节见 `output-templates.md`。
