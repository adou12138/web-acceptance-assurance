# Web 新需求测试方法论

## 定位与输入

本专家面向新功能提测、既有功能改版和修复后复测。优先取得：本次需求说明/原型或变更列表、测试地址、测试环境、可用角色与登录方式；有源码、接口文档、旧版行为和历史缺陷时用于补充分析，不强制要求。已有上下文直接复用。

仅需求时产出规格与用例，运行状态为 NOT_RUN；仅网址时能做页面检查与探索，但需求符合性因缺验收依据保持待核实；需求加网址即可进行新需求黑盒测试，不以无源码阻塞。未知版本记录“版本未提供，观察时间与环境如下”，不能虚构提交号。

需求预审逐条检查完整、明确、一致、可验证及新旧兼容性，特别核对默认值、角色权限、合法/非法状态、边界、错误恢复、时间精度、空/加载/失败态和数据保存删除。需求缺失/冲突、实现缺陷、主观体验建议分账，来源与观察分别记录；未知业务规则不从当前实现倒推。界面样式、用户体验易用性与基础无障碍默认评估适用性并执行可做部分，规则见 `visual-usability.md`；无设计稿不阻塞客观问题检查。

## 主流程及阶段产物

| 阶段 | 要做的事 | 可核验产物与进入下一阶段条件 |
|---|---|---|
| 需求拆解 | 提取本次新增/修改点，比较旧/新行为，识别歧义、开关、角色、数据和依赖 | 需求清单、差异清单、待确认问题；明确部分可继续 |
| 功能与场景建模 | 按业务域组织功能→功能点两级清单，每项说明业务职责；列跨功能场景与正向/边界/异常/权限路径 | FUNC/FP/SCN/PATH ID、目标、覆盖关系和不适用理由 |
| 验收与覆盖检查 | 每条业务规则给可观察结果；检查功能点、业务路径和角色分支，复杂流程按需画图 | REQ/AC 编号、来源、确认状态、覆盖缺口及图/评审决定 |
| 用例设计 | 正常、边界、异常、权限、状态和组合分析，选取业务闭环 | 用例与追溯矩阵；每例有前置、数据、动作、预期和观测入口 |
| 环境冒烟 | 目标可达、版本与开关、账号、关键依赖和最小业务闭环 | 最小 smoke 清单及耗时；失败仅阻塞依赖该前提的用例 |
| 新需求实测 | 核心验收与定向探索交替，逐批补边界/异常/权限与相关专项；覆盖 UI 和可用接口观测 | 本轮执行记录、实际业务断言、日志/截图/trace 等证据 |
| 影响面回归 | 新需求改动→共享组件/接口/状态/数据→旧功能→回归子集，随发现增补 | 选择理由、已选和未选范围、遗漏风险；未知依赖列为缺口 |
| 定向探索 | 从初次观察起穿插正式用例，围绕高风险和脚本盲区按章程与预算选择下一步 | 实际会话记录、选择依据、未探索前沿、发现和可固化用例 |
| 缺陷与复测 | 记录复现与建议，修复后复跑原场景和邻近影响面 | 缺陷状态、复测证据、回归资产与残余风险 |
| 交付 | 区分技术结论与业务签收 | 范围限定结论、证据矩阵、缺陷、未测项及复评条件 |

用户只要求需求评审或设计用例时止于对应阶段，明确尚未执行；用户要求测试且条件具备时继续执行。已授权的常规操作不逐步重复确认。环境、工具或数据不足时，完成不依赖该阻塞的部分，再准确列出补齐项。

## 正式用例与自适应探索循环

冒烟后，以一小批正式用例和一段定向探索交替推进，不将探索、视觉或体验检查统一延后至正式用例结束。每批执行“观察→更新覆盖与未探索前沿→按风险选下一项→核对授权/前置/副作用→实际操作及强断言→记录与回填”。简单任务沿用现有清单，复杂任务使用 `exploration-runtime.md` 中的轻量清单和候选工具；具体格式依该契约，不另造平行规格或业务裁决器。

- 从实际页面、链接、表单、动作与真实请求建立页面—组件—角色—状态—数据观察映射，关联现有FP/SCN/PATH/TC/EXP/RUN；未观察到的路由、endpoint和状态仅能标假设，不能当真实覆盖。功能入口不等于业务场景，每次点击不单列一个场景。
- 未探索前沿保留实际入口或触发方式、已知前置、角色/状态/数据/视口组合、风险与未知、选择或暂缓理由。按业务影响、未知程度、异常线索和剩余预算选下一项，候选排序不等于授权或必选验收排序。
- 优先实际可安全触发的反向操作、返回/刷新/重开、切换、撤销、重复提交和相邻边界；检查默认、加载、空、错误、成功、禁用、无权限及弹窗/抽屉/页签/悬停/焦点状态。状态必须实际触发并取证，无法触发列缺口；不随机点选、不盲猜隐藏地址、不自动重放未知写入。
- 一般组合可成对选样，高风险多维交互单列用例；记录不可达、未选组合及原因。出现异常扩查同类字段、共享组件和相邻状态，按现象去重但保留不同业务影响，根因未明不得合并为同一根因。
- 操作受理、超时或会话中断后，先以业务ID/任务状态/读回核对原操作和副作用，再决定继续、恢复或有限重试；恢复失败保留残留与阻塞，不为探索重复写入。跨角色/用户/租户只使用获授权账号和数据，缺账号或不明边界只阻塞对应前沿。
- 每段EXP记录目标/风险章程、预算、实际路径、关键观察、TC/RUN/BUG关联、下一步依据和停止原因。新增可执行路径回填既有用例，必要时按执行管理契约更新规格轮次，不能默改冻结基线或宣称候选已执行。预算耗尽可停止探索，但披露高风险未探索项；必选验收未满足仍按结论规则待核实或不通过。

观察器或候选工具只产生有限采集事实与线索，专家仍须打开真实页面、核验适用性和业务判据。脚本退出成功、空issues或候选全部处理，不证明需求符合、视觉合格或探索穷尽。

## 轻量测试计划与阶段条件

复用本次范围、风险和执行基线，按任务规模记录目标、范围/排除项、测试策略、环境/数据依赖、工作批次及顺序、预估工作量与依据、参与人或待指定、进入/停止/恢复/完成条件、交付定位。简单任务用简短清单即可，不默认另建计划文件；已有授权继续执行，不把计划记录变成额外审批。人员、排期和承诺日期只能引用真实安排；未知则列依赖与待协调项，不替团队分派或承诺。

- **进入**：目标版本与需求范围可识别，相关判据、角色、数据及观测条件可用。需求设计可在未部署时先做；功能执行前完成相关环境冒烟。
- **停止/恢复**：区分业务失败与环境阻塞，记录受影响TC、停止原因、恢复条件和仍可继续的独立部分；恢复前核对版本、初始状态与已有副作用。
- **阶段完成**：设计完成意味着规格、覆盖及缺口已记录；执行阶段完成意味着计划项有当前有效结果或明确未测/阻塞记录；技术验收通过仍须满足既有必选AC/TC及证据规则。三者不能互相替代。
- **测试完成与发布决定**：交付报告不表示必选项全部满足；准出未达时明确不通过或待核实。用户要求上线评估时给出风险建议、依据、残余风险、下一步及业务接受责任人（未知待指定），发布决定由项目责任人作出。

## 兼容性矩阵与选样

涉及浏览器、布局、上传下载、输入法或客户端环境差异时，根据产品支持范围、已有用户分布、历史问题与本次变更选择测试组合；没有资料则把建议样本标暂定，不能声称覆盖全部用户。以“操作系统及版本、浏览器及版本/内核、视口、实际设备或模拟方式、角色/开关、目标TC”为组合记录；嵌入式WebView仅在本次范围内追加宿主版本。

必选支持组合及高风险场景单独执行；其余可按风险抽样或成对组合，记录未选理由。只改变视口不代表更换真实设备、操作系统或浏览器内核；浏览器模拟也不证明真机、真实网络与宿主能力。用同一业务TC关联不同环境的独立RUN，不为每个组合复制一套需求；矩阵汇总按(环境组合, TC ID)计算，整体用例总数仍按TC ID去重，不能把单浏览器通过外推全矩阵。

已有台账按轮次冻结上下文，多环境组合分别建兼容轮次或独立工作目录，并在环境标识/上下文中包含完整组合，防止环境哈希相同而复用错误结果。跨组合汇总由专家核对，不声称execution_ledger.py已自动汇总矩阵。缺少真实目标浏览器/设备时只运行可做部分并列覆盖缺口，不把模拟等同替代证据。

## 功能点、场景与用例的分析顺序

业务域用于归组，不强制再建一层节点；两级结构是“功能→功能点”。每项有稳定 ID、名称与一句话业务职责；同名允许通过 ID 区分，但应尽量使用清晰名称。场景是一条有业务目标、可跨功能点的旅程，不能拆成每次点击，也不能仅用模块名代替。为每场景列正向、边界、异常、权限路径，路径有 ID 与预期方向；未适用或缺规则需说明。

先用功能点视角检查局部，再用场景视角检查端到端分支，必要时以真实接口 method+path 检查后端断言。流程图/状态图用于复杂分支、异步和状态流；图引用 SCN/PATH，不能画出未在规格中说明的假设规则。简单 CRUD 可只用简明清单。没有场景的简单需求须以 AC/FP 检查覆盖，不能用省略场景绕过边界分析。

根据风险决定是否需要人工评审，复用已有确认；简单任务及已授权执行不强制分两轮等待。决策记录说明拆分理由、范围裁剪、图是否需要、分类依据与待确认问题。明确部分继续推进。文件化资产格式和包内校验工具见 `case-data-contract.md`。

## 新需求覆盖检查表

以下维度逐项评估适用性；不适用说明理由，未测项保留。没有相应业务风险时不机械制造用例。

| 维度 | 典型检查 | 方法 |
|---|---|---|
| 业务主路径 | 新入口、开关开启/关闭、成功结果、上下游闭环 | 场景法、真实旅程 |
| 表单与边界 | 必填/可选、空/空白、最小/最大及相邻值、类型、精度、长度、格式 | 等价类、边界值 |
| 规则组合 | 多条件同时满足/冲突、默认值、互斥项、优先级 | 判定表、成对组合；高风险组合专项补齐 |
| 状态流转 | 初始/处理中/成功/失败、非法转换、撤销、重复提交、返回刷新 | 状态迁移、不变量 |
| 角色与会话 | 不同业务角色、未登录/过期登录、前后端权限一致性 | 权限矩阵；仅在授权角色与范围内验证 |
| 数据与持久化 | 保存回显、刷新重开、列表/详情一致、编辑删除约束、历史数据兼容 | 可观测业务读回；不能以 UI 提示代替持久化 |
| 异步与失败恢复 | 超时、接口失败、网络中断、重试、重复事件、处理中再次操作 | 错误推测、有限故障模拟，记录模拟边界 |
| 展示与交互 | 默认评估并实际检查空/加载/失败态、禁用态、遮挡重叠/截断溢出、布局位移、图片比例、字体与可读性、响应式 | 真实截图结合实际几何与交互；有需求/设计/确认旧版基准时对照，无基准不声称像素一致 |
| 易用性 | 默认评估任务入口可发现性、交互一致性、操作反馈、错误预防/恢复、任务负担与输入数据保留 | 按真实任务实际操作，记录影响与依据；主观建议分账，专家评审不冒充用户研究 |
| 基础无障碍 | 默认评估并实际检查键盘可达、Tab顺序、焦点可见/弹窗焦点、标签/替代文本、非仅颜色提示及适用减少动态效果 | 用实际页面验证可做部分，无法检查列缺口；不冒称完整WCAG或辅助技术认证 |
| 旧功能影响 | 共享组件、接口字段、查询/排序/分页、旧数据、前后兼容 | 变更与依赖分析 |
| 兼容与性能 | 目标浏览器/系统/视口，导航加载、交互时序、资源和卡顿 | 风险抽样与实际工具，多次采样；模拟不外推真机，测量不外推容量 |

## 支撑设施控件盘点

按本次需求触达的页面/弹窗清点**支撑设施控件**：文件选择器、下载/导出入口、剪贴板、日期选择、富文本、上传队列、分页、导入模板等。这些控件是外部反馈高发区（导出失败、按钮置灰、剪贴板无效等），但常因“主功能有用例”而被整块跳过。盘点产出逐控件条目：可交互性、当前态、依赖通道（文件系统/下载落盘/剪贴板权限），无对应用例的控件写明原因。与 `exploration-runtime.md` 的控件遍历条目（`EXP-TRAV-`）配合：遍历清点控件存在性，本表核对每类控件是否有验证设计。

## bug 高发模式补集

以下 4 个模式是既有清单的**补集**：默认/加载/空/错误/成功/禁用六态见本章“正式用例与自适应探索循环”的探索循环条目，长文本溢出由 `browser_observer.js` 的 text-clipping/horizontal-overflow 规则覆盖，此处不重复表述：

| 模式 | 典型表现 | 设计/检查要点 |
|---|---|---|
| 状态残留 | 跨 tab 切换后旧按钮/提示仍在、高亮不消失、跳转后弹窗不关 | 每个异步提示记录“何时消失”；切换/返回后核对旧态 |
| 双入口/双视图不一致 | 创建 1 个字段保存后变 2 个、页面 vs 导出、列表 vs 详情 | 同一对象至少两个视图交叉核对字段数与值 |
| 死按钮 | 点击无反应、无提示、无网络请求 | 死按钮须留网络请求证据（发了什么/什么都没发） |
| 枚举外取值被改写 | 原文「开车出门」被归类改写为「通勤」 | 自由文本归枚举时核对原文与归类的可追溯映射 |

## 异常路径构造四问

凡场景含异步任务、文件上传、导出、网络依赖或长任务，逐问回答；每个回答要么转成 exception 路径用例，要么按 `case-data-contract.md` 的 `not_applicable` 对象形态写具体举证（reason 写页面依据，business_object 指向本场景业务对象）：

| # | 必答问题 | 典型缺陷形态 |
|---|---|---|
| 1 | 异步任务中途取消/离开页面/超时后回来，状态如何？提示是否常驻？ | 提示跨 tab 残留、取消后任务仍在跑 |
| 2 | 上传/导出失败时，用户看到什么？能否重试？有无残留脏数据？ | 导出静默失败、上传失败无提示、脏数据残留 |
| 3 | 必填/前置未满足时，拦截提示是否可理解、是否可恢复？ | 拦截点击无反应、标识必填却可跳过 |
| 4 | 重复点击/并发操作同一对象，是否产生重复数据？ | 重复提交产生双记录、并发合并互相覆盖 |

## 业务风险与专项选择

功能点和场景建模时，用下列清单对照本次变更及依赖，形成“触发依据→可能失效→业务影响→验证方法→TC/缺口”记录。知识库条目是风险假设，不是需求事实或已证实缺陷；每条需结合实际业务确认。只有涉及对应模块或明确影响面时才选择专项，不因模块名、关键词或指令名称自动扩范围。

| 业务触发 | 重点风险与组合 | 业务断言及观测 |
|---|---|---|
| 登录、会话、角色或租户变化 | 登录过期×未完成操作；菜单×按钮×接口；角色/租户切换×权限缓存 | 在授权测试账号和自有数据间验证拒绝及数据隔离；失败操作不改变业务数据，不仅检查按钮隐藏 |
| 上传、预览、下载 | 文件类型×大小边界×重名；上传中断×重试；下载×资源归属 | 使用无害测试文件，按确认规则判断接受/拒绝；核对内容、归属、失败残留和恢复；不凭后缀或MIME单一信号判断安全 |
| 批量导入、导出 | 模板版本×字段规则×重复行；进度×任务并发×错误报告 | 先确认全量回滚或允许部分成功的规则；核对成功/失败/跳过数量与持久化结果、错误行定位；批次不串数据 |
| 支付、退款、额度或订单联动 | 状态×重复/延迟回调×金额精度；取消×退款×超时 | 只在授权测试/沙箱边界内执行；按真实精度、舍入及状态规则核对订单和可观测流水，不由提示成功推断资金正确 |
| 异步任务、消息、通知 | 重复事件×重试×补偿；乱序×超时×用户再次操作 | 记录业务关联ID、完成信号及允许延迟；断言最终状态、业务副作用次数和通知对象，队列ACK或发送成功不替代业务完成 |
| 搜索、列表、报表 | 筛选×排序×分页；新增/编辑×索引或缓存延迟；导出×权限范围 | 核对集合、稳定排序及翻页重漏、空结果、详情/汇总/导出一致性；样本正确不外推全量正确 |
| 审批、规则配置、发布开关 | 角色×状态×撤回/驳回；规则优先级×冲突；新旧配置×缓存 | 按确认状态图/判定表验证合法及非法流转；核对历史数据、已在途实例和变更生效范围 |
| 时间、区域或多环境差异 | 截止点前/当时/后；时区×日期跨界；浏览器×角色×开关 | 使用约定业务时区、时钟来源、包含/排除边界；阈值未知先澄清，不从本机时钟臆定业务规则 |
| AI生成或异步生成页面 | 固定输入×输出结构×超时/重试；取消×流式中断×再次生成 | 分别核验结构、保存/读回、用户可见质量及失败恢复；质量量表需有来源，非确定输出用确认样本和重复观察，不以一次文本相同为唯一判据 |
| 离线、本地存储、同步或旧数据迁移 | 保存×刷新重开；断网暂存×恢复；多端冲突×同步提示；旧样本×迁移；清空×再使用；日期跨界 | 在实际功能存在时用测试数据核对前后内容、冲突处理、恢复和可用性；多设备/存储配额/旧版样本缺失列缺口，不替产品设定覆盖策略 |
| 电商商品、促销、库存或售后 | 优惠叠加/互斥×定金尾款；精度×库存预占释放；重复下单×取消超时退款售后 | 按确认规则核对订单业务ID、金额、库存和状态读回；仅在授权测试/沙箱执行，真实资金及库存影响单独确认，不编造优惠优先级和退款时限 |
| 埋点、归因、转化记录或外部分析平台 | 触发时机×次数×属性；匿名/登录标识×跨端；刷新/重试×去重；依赖失败×主业务 | 观察真实事件请求或数据层，核对需求规定的属性和频次；发送侧与接收处理/入账分层，脱敏用户字段；无接收权限不能宣称平台记录成功 |

风险按影响和可能性排序，保留评分依据与未知项；未知不默认低风险。高风险用例优先执行，但风险级别不直接等同缺陷严重度。无接口、数据库或消息观测时采用页面读回等可得证据，明确未核验边界；不能据本表宣称已具备后台管理权限。并发、大文件、回调重放和故障注入需实际环境支持与对应授权，缺失时登记缺口，不扩大常规测试的副作用。

## 逐类适用性裁定

功能、安全、性能、无障碍、兼容、视觉、可靠性七类默认都要给出裁定，不能因为没测就静默跳过。每类记一个状态与理由：

- **适用**：有对象、触发条件和检查关注点的依据，应设计并执行测试。
- **不适用**：能说出该类为什么不需要测（如需求未声明端差异、未涉及鉴权），可结案。
- **证据不足**：缺材料（无阈值、无设计基线、无对应角色账号），写明缺什么；不计为已覆盖。
- **本轮暂缓**：有依据但受范围或预算限制，列入未覆盖义务并写清补测条件。

「证据不足」与「本轮暂缓」继续留在分母和风险清单里，不算通过。结构化数据用顶层 `applicability` 承载：`case_data.py` 会检查状态取值合法、不适用或暂缓必须给理由、以及是否存在未裁定的类型。七类全裁、理由可读，比"这次只测了功能"更接近真实覆盖。

## 接口、事务与隔离专项

页面到接口联合观察使用实际动作、真实method/path、业务关联ID及脱敏请求响应，核对参数必填/类型/范围、错误码、分页排序、响应字段和上下游失败，再比对页面提示及最终业务读回。有OpenAPI/消费者契约时核对来源与版本兼容，无协议则记录观察与待确认差异，不编造endpoint。网址访问授权不自动包含任意重放、篡改或扩展接口扫描；抓到请求也不代表有权修改对象。

涉及保存、导入、任务或订单时，按确认规则分别验证有限双击/重复提交、超时重试、处理中刷新/取消、部分成功、重复/延迟/乱序结果与失败恢复，记录业务ID、前后状态、副作用次数和归属。区分全量回滚与允许部分成功、幂等键或业务去重及完成信号；受理不等于完成，超时不等于无副作用，先查原任务再重试。黑盒读回可证明观察到的一致结果，不能证明内部事务原子性；更深回调重放、故障注入和内部日志检查需对应环境与授权。

匿名、本角色、其他角色、其他用户和租户矩阵仅使用获授权测试账号及自有数据。检查会话过期、退出后访问、直接入口、菜单/按钮/合法接口观测、权限缓存及敏感展示；失败操作应保持数据不变。只有一个账号不能证明跨角色隔离；账号不足列对应缺口。记录中去除口令、cookie、token和个人信息。漏洞扫描、恶意载荷、跨账户对象修改或渗透须额外明确授权，常规安全观察不以缺扫描工具为由省略。

## 条件专项的执行与证据边界

仅在实际功能或明确影响面触发时启用下列专项，不要求普通网站新增这些能力，也不把“用AI测试网站”等同于网站具备AI功能。

- **本地数据、离线、同步、导入导出与迁移**：按空、单条、大数据及无效输入选样；实际导出后用可用解析能力核对内容、数量、格式与日期，再在获授权测试数据上导入读回。检查断网暂存/恢复、同步指示与冲突策略、清空后可用、旧数据迁移及存储配额；策略来自需求，不默认时间戳覆盖。网络/多设备/旧版数据不可控时保留未测项，不以默读代码或心中模拟作实测。
- **电商订单与促销**：关联促销、金额精度、库存预占释放、订单和售后状态，按合法/非法状态及支付前后恢复交叉验证。沙箱/真实依赖分别标识；模拟支付不能证明真实资金核验，A/B转化结果不能替代功能判据。
- **埋点与外部依赖**：留事件名、动作、属性、实际次数、脱敏请求及接收端观察范围；依赖异常不得破坏主业务。频次、标识和去重规则来自需求，不能自行认定刷新必须只报一次；避免重复污染正式分析数据。
- **网站AI功能**：覆盖业务规则幻觉、多轮上下文、同义等价输入、输出结构、持久化读回、随机性、失败恢复及适用隐私风险。记录实际输入/原始输出/轮次/样本量与可得模型版本参数，固定参数不保证确定。质量量表和可接受性需确认，模型自评不能独立定PASS；修复后用不同等价表述回归。指令干扰仅限获明确授权的AI评测范围，不读取或诱导披露无权数据。
- **页面性能**：分别观察导航、主要内容、布局位移、关键交互、长任务、资源错误/体积及大列表卡顿；在相近浏览器/设备/网络/数据量及冷暖缓存条件下多次采样，保留工具版本、原始样本和环境干扰。LCP/INP/CLS仅在有效采集时报告，缺交互样本不得将INP报0并判通过；无样本不报分位数，无确认阈值先给测量/比较/风险，不自设失败门槛。真实用户与实验室数据分开，单次很快或工具高分不外推所有用户。
- **负载、容量与可靠性**：单请求时序、并发负载、容量上限、故障恢复分开。先确认目标环境、业务目标、负载模型、并发与时长、数据、监控和停止条件；只有对应授权且工具真实可用才发起。保留请求级时延/错误样本、吞吐、资源、基线和恢复证据，总耗时除并发数不等于请求均值或P95。常规网页观察不自动扩为压测或故障演练，未执行明确写专项缺口。

界面样式、易用性、兼容及基础无障碍具体执行参照 `visual-usability.md`，并同步于正式旅程和探索；仅截图或有限DOM采集不能替代真实交互、人工复核与业务判据。

## 组合场景到可执行用例

1. 从已触发风险中选择一个业务目标及具体失效路径，关联已有REQ/FP/SCN/PATH，不重复建立一套编号或场景库。
2. 列出有业务含义的维度和取值、不可达组合、规则来源与依赖。例如导入维度可为模板版本、校验结果、任务状态和重复提交；不能仅列维度名而无具体输入。
3. 优先覆盖关键不变量及已知高风险交互。一般组合可用成对覆盖降低成本，三维以上联动风险或历史漏测需补专门用例；成对覆盖不等于穷尽，不强制生成全笛卡尔积。
4. 明确真实角色、初始状态、具体测试数据与恢复方式，将路径展开为单步动作和可判定预期；独立数据组合使用独立TC，套件复用同一TC。
5. 为每个TC绑定业务断言、观测入口、优先级、套件及证据要求，记录已选/未选组合和理由。具备执行条件时继续实际运行；只有场景树或脚本骨架时仍为NOT_RUN。

教学示例：若已确认规则是“导入允许部分成功、同批次重复请求不新增数据”，可构造3行有效与1行无效数据，断言成功3/失败1、错误报告指向真实错误行，并以可观测读回确认仅3条入库；重复提交核对数量不增长。若实际规则为全量原子提交，则预期应为整批拒绝且零新增；规则未知时不得任选一种当产品标准。此例没有在真实网站执行。

## 测试预期与断言复核

先检查测试是否有可靠判据，再用它判断产品。每个关键断言核对：来源及版本、适用角色/状态、预期业务值、观测入口、时间窗/误差和失败后的归因路径，并区分机械判定、专家判断、模型辅助与必须真实执行的观察。比较应使用独立依据，如确认的判定表、经核验的数据集、独立计算或可观测不变量；不能复制被测算法或用同一接口值同时生成实际与预期，形成自证。HTTP200、toast、按钮可点击、截图正常或没有控制台错误均不足以独立证明业务闭环；保存后应按AC刷新重开、比较列表/详情/相关读回，拒绝后核对未错误新增或改坏。

覆盖成功和拒绝后的不变量：不仅检查成功结果，还核对错误操作未产生未授权写入、重复扣减或残留。确认异步等待上限及完成信号；未知阈值保持待确认。需求、规则、数据或环境变化时检查断言是否漂移，遵循execution-management.md的新轮次与失效规则，不修改预期来追随错误实现。

输出或自动化草稿由AI生成时，逐项核对可追溯来源、步骤可执行性、具体数据、断言独立性及高风险组合缺口；区分必需业务确认和专家可完成的内容复核，不强制所有测试额外等待人工审批。假设未确认只阻塞相关判定，其余明确测试继续。

设计方法要有见证才算覆盖，只写方法名称等于没写：说用了边界值，就给出具体的最小值、最大值和越界值；说用了等价类，就给出有效类与无效类的具体取值；说用了状态迁移，就给出源状态、目标状态与触发条件；说用了判定表或组合覆盖，就给出条件项与动作项的对应关系及已覆盖的参数对。没有取值、没有边、没有对应关系的，按未覆盖处理，不能用方法清单充数。同一条断言也不能靠"预期来自被测实现本身"闭环，预期必须另有来源。

## 优先级与分层

P0 为无法完成新需求核心目标或可能造成高影响数据错误的场景；P1 为主要规则、常见边界与关键异常；P2 为低频组合和低影响体验。优先级与缺陷严重度分开，具体清单在方案中说明。风险可参考影响程度×发生可能性，不把默认数字当通用门禁。

测试分层按可观测性与成本选择：复杂规则组合尽量在组件/接口层验证，保留关键用户 E2E。仅网址无法证明单元或代码覆盖。不得按固定比例凑用例，也不得以“有测试目录”判定覆盖有效。

## 套件职责

- **smoke**：最小环境与业务可测性集合。给出合理时间预算及其依据，实际测量耗时，不把示例五分钟硬编码。冒烟只标「入口能否正常打开、核心数据能否加载展示、核心操作能否完成」三类；异常场景（权限不足、空数据、超时）、删除/禁用等破坏性操作、次要字段核对和纯界面细节不标冒烟。小任务可以没有独立冒烟集，但不得用冒烟代替覆盖证明。
- **feature**：本次新需求的正常、边界、异常、权限和状态场景，是主要工作量。
- **e2e**：新需求完整旅程；标识真实/沙箱/mock/replay 和替换边界。
- **regression**：受影响的旧功能。可与 feature/e2e 复用用例，保留同一 case ID，报告总数按 ID 去重。
- **exploratory**：有章程的风险探索，探索时间不冒充用例覆盖数。

## 传递影响与回归候选

依赖必须有来源，方向明确为“A依赖B”：B变更可能影响A，不能反向套用。由直接变更REQ沿反向依赖逐层追踪，保留每个变更源到受影响需求的一条确定最短路径、边的依据及关联TC。环形依赖用已访问集合终止，不重复计数；多源影响分别留路径。路径不是全部可能关系，输入图不证明实际业务或代码依赖完整。

使用本包 `scripts/change_impact.py`，它先调用 `scripts/case_data.py` 校验现有设计，再以FP.requirement_ids和AC.requirement_id映射TC，按P0/P1/P2及ID排列候选；实现验证见 `tests/test_change_impact.py`。未知/重复ID、直接自依赖和无来源关系拒绝；未提供依赖时只分析直接变更并显式提示间接影响缺口。设计结构本身缺AC/TC时先报告结构错误；结构合格但已知图不完整时仍需专家补查共享组件、数据和业务旅程，不解释为无影响。

变更输入为独立JSON（不改设计格式）：schema_version为"1.0"、changed_requirements为非空已知REQ ID数组、dependencies为数组；每项含requirement（唯一已知REQ）、depends_on（非空不重复已知REQ数组）和source（非空来源）。同一requirement的多条依赖合并在一个数组，循环可处理但直接自依赖拒绝。

```bash
python scripts/change_impact.py <cases.json> <changes.json> --output <新的regression.csv>
```

路径相对包根；其他工作区换绝对路径。命令返回JSON分析，按需输出utf-8-sig、逗号分隔CSV；拒绝覆盖已有文件，父目录须存在。退出码0仅表示候选分析完成，输入/输出错误为2，不是测试或门禁结果。CSV为候选入口，传播路径、来源和缺口在分析结果中；需要文件留存完整结果时由专家写入本轮manifest/回归说明，不从CSV反推完整图。候选保留历史通过用例，既不改执行状态也不证明回归已跑；回归子集通过仍不能代表全部需求验收。

## 回归资产维护

每个可复用回归资产记录 TC ID、需求/缺陷来源、资产版本、目标应用版本范围、脚本或手工步骤路径、所需数据/角色、维护责任人（未知待指定）、执行入口、最近一次有效 RUN 和维护状态。脚本框架已存在时给出可重复命令与数据前置；无自动化条件时保留可重跑的手工步骤，不强制改建 CI。CI 可用时检查实际 job、触发条件和结果关联，并在已有授权内接入测试；未接入时准确写明人工入口和自动化缺口，不声称已持续运行。规格变化需同时更新关联用例和回归标签，废弃资产保留变更原因。

## 线上问题与漏测复盘

仅在任务涉及线上问题、历史逃逸缺陷或用户明确要求时开展，不把每轮新需求测试扩成持续生产巡检。先引用实际影响、版本/环境、发生与发现时间、关联BUG/TC/RUN、脱敏日志和已采取措施，梳理带时区的事实时间线；没有证据的原因单列假设和验证方法，不以“测试没覆盖”直接认定根因。

分别核对产品失效原因与测试逃逸原因：需求或预期是否缺失、用例是否遗漏、已有用例是否未运行、环境/数据是否失真、断言是否过弱、结果处理是否不当。缺少历史记录写“未找到/待核实”，不能写“未执行”。从已证实原因提出修复和防再发动作，每项记录责任人（未知待指定）、目标日期或待协调、产物/TC/回归入口、验证方法、有效证据和状态。补用例只证明资产补齐，仍需实际复测验证。

按需统计漏测时写明统计窗口、版本、问题归属和唯一缺陷ID去重规则；线上发现不自动等于本版本引入。复盘关闭需对应改进项的验证证据，不能用修复问题替代流程改进完成。生产排查先使用已有只读材料，主动探测、写入、压测和部署按对应授权执行；没有监控通道或持续调度时不宣称已建立上线后监控。

## 最小复现与竞争假设

原始失败先冻结证据，再在安全边界内逐步减少动作、输入和依赖；最小复现保留必要角色、数据初态、版本与时序，缩减失败也保留原场景，不能删掉原前置使问题消失后宣布已修复。产品、环境、数据、脚本、不稳定和待归因分别记录。对重要不明失败列出合理竞争假设、各自支持/反对证据、置信度及依据、最小证伪动作与结果；置信度不代替证据，不虚构源码根因。相同表象的不同入口或影响先关联，不在缺乏原因证据时合并。修复建议受可见信息约束，复现次数与有效业务尝试按执行证据契约统计，不能重跑到变绿抹去首败。

## 覆盖复核与交付

每批结束从REQ/AC反查TC及当前有效RUN，从实际页面/组件/角色/状态/数据组合反查遗漏规格，再从BUG/EXP反查共享组件及同类影响。单列未探索前沿、未运行、阻塞、隔离、待核实及未选组合，区分资产完整、执行覆盖、需求满足和业务签收。风险未知不视为低风险，候选存在不代表用例已跑。简单任务在现有记录中完成复核，不为清单另设审批。

结果类文件对外交付使用 UTF-8-sig、逗号分隔CSV，交付前复读核对中文、列数、ID关联、证据位置及可复算分母。内部设计JSON、台账、观察协议及派生YAML保持现有契约与单源关系；CSV是交付视图，不替代规格源、执行事实源或缺陷状态源。需求缺失/冲突、实现缺陷、主观体验建议分账；专家评审不得标作用户访谈、用户测试或满意度研究。

## 专家能力效果验收

仅在用户要求专家升级效果验证时开展，不将普通网站任务扩为专家评测。使用隔离受控站点及含已知歧义的需求，评估者预先冻结隐藏缺陷答案和统计规则；旧版与当前包在相同工具、账号、数据、授权和预算下独立运行，适当重复，执行者事先不知缺陷位置。分别核对真缺陷发现、误报、需求缺口、证据可复核性、剩余风险和执行成本，保留原始运行与对照统计；答案泄露、共享数据污染或环境不等价时说明无效或受限。

用真实浏览器执行正常反例、近似但不成立的异常、登录阻塞与工具恢复；条件具备时补视觉动态误报、性能样本、并发及隔离专项。判定基于独立答案及实际证据，不以模型自评替代事实，不照搬固定通过率、响应时间或提升数字。文件变更、结构校验或脚本单元测试通过只能证明对应资产，不证明真实网页测试效果提升；未运行受控网页验收时必须明确未验证效果，不将基准结果外推全部网站。

受控站点自身的预埋项只用于校验采集与判断链路：检出后记为“按要求检出预埋项”，不得写进产品缺陷清单、缺陷率或能力结论，也不得列为待跟进的真实缺陷。交付前若发现把预埋项当产品缺陷，属结论口径错误，必须改回；页面自述为夹具时，观察器与桥接会带标记提示，但最终由人确认用途。

## 质量结论

结论严格按 agents/web-acceptance-assurance.md 和 execution-evidence.md。必选用例不得通过事后取消必选、改分母、隔离或删除失败记录来获得“通过”。范围变化保留原因和旧范围对照。紧急交付可建议先跑最小高风险集合及后续补齐，但未测风险和未知结论必须保留。
