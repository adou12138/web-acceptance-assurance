# 安全防护验证（外部可观察，不做攻击）

> 定位：`business-pitfalls.md` §11 是"往哪看"，本文件回答"**怎么从外部确认防护是否存在**"。
> 纪律：只做防护验证——只读观察、正常输入、自有账号；不构造攻击载荷、不扫描第三方资产、
> 不使用他人账号、不做压力与绕过尝试。发现可疑即记"疑似"并转安全团队，**不在验收结论里定性为漏洞**。

## 〇、动作许可分级与授权边界

每条目按动作与副作用标注许可分级，越界动作不做：

| 分级 | 定义 | 典型动作 | 前置要求 |
|---|---|---|---|
| L1 只读观察 | 不产生任何写副作用 | 看响应头、控制台、页面回显、静态资源清单 | 正常访问即可 |
| L2 可逆写 | 副作用可完全恢复（自建数据、可删除/撤销） | 自有账号创建资源、提交自建表单 | 测试账号 + 可还原路径 |
| L3 不可逆写 | 副作用不可完全恢复（锁定、计数消耗、状态流转） | 触发失败锁定、消耗验证码/尝试次数 | 明确授权 + 隔离环境 + 留痕 |
| L4 注入/异常输入类 | 构造异常输入或改写参数做探测 | 改名文件上传、畸形输入、越权访问尝试 | 明确授权且仅限隔离环境 |

- 注入类（L4）与越权类操作必须有明确授权且仅限隔离环境；生产或共享环境一律不做，只保留 L1 观察。无授权时对应条目整条记"未验 + 原因"，不降级为"已验"。
- 登录凭证规则与 `agents/web-acceptance-assurance.md` 对齐：登录由用户在有头窗口手动完成，**不自动填密码、不读 Cookie**。验证 Cookie 属性只观察 `Set-Cookie` 响应头，不提取、不存储、不重放真实凭证；涉及本人会话的登出验证结果即记即弃。
- 每条动作执行后须**副作用恢复/留痕**：L2 收尾还原或清理并记录；L3 在条目证据中登记消耗量与不可恢复项；L4 探测产生的数据与文件按归属清理；L1 留证据文件即可。清理仅限本人/授权范围内数据。

## 一、十二条可外部验证的防护

### 1. 安全响应头

- **许可分级**：L1 只读观察。
- **怎么验**：浏览器开发者工具 → 网络 → 主文档响应头，或 `curl -I <页面地址>` 只读获取。
- **看什么**：`Content-Security-Policy`（存在且非 `unsafe-inline` 全开）、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Strict-Transport-Security`（HTTPS 站点）、需要嵌框防护时有 `frame-ancestors` 或 `X-Frame-Options`。
- **证据**：响应头原文。
- **副作用恢复/留痕**：无写副作用，留存响应头截图或文本即可。
- **不算缺陷**：纯内部工具且已有网关统一注入（须给出网关证据）；页面为静态 CDN 且策略在边缘配置。

### 2. Cookie 与会话属性

- **许可分级**：L1 只读观察（响应头与页面可见性）；登出验证为 L2 可逆写（登出本人会话）。
- **怎么验**：登录后观察 `Set-Cookie` 响应头属性与 `document.cookie` 的可见性（只观察，不提取、不存储 Cookie 值）。
- **看什么**：会话 Cookie 有 `HttpOnly`、`Secure`（HTTPS）、`SameSite=Lax/Strict`；无超长有效期；登出后服务端失效（用本人已登出的会话重访受保护页应被拒，结果即记即弃）。
- **证据**：`Set-Cookie` 属性原文（值打码）+ 登出后重访受保护页的结果。
- **副作用恢复/留痕**：登出属本人会话操作，无他人影响；验证后重新登录恢复现场。
- **不算缺陷**：非会话类偏好 Cookie 无 `HttpOnly`（前端需读取）。

### 3. 前端包中的密钥与调试信息

- **许可分级**：L1 只读观察。
- **怎么验**：只读检查构建产物中的配置对象与 sourcemap 是否公开。
- **看什么**：无数据库口令、私钥、第三方 `secret`、内网地址；sourcemap 未公开暴露源码（或确属有意）。
- **证据**：命中的变量名与文件路径（**值要打码**）。
- **副作用恢复/留痕**：无写副作用；发现的疑似泄露值一律打码留痕，不上传原始值。
- **不算缺陷**：公开的 `publishable key`/`anon key` 且权限由服务端 RLS 控制（须确认策略存在）。

### 4. 开放重定向

- **许可分级**：L4 注入/异常输入类（改写跳转参数属异常输入探测），须明确授权且仅限隔离环境。
- **怎么验**：找到带 `redirect`/`next`/`returnUrl` 参数的跳转，把值改为站外地址（如 `https://example.com`）。
- **看什么**：应拒绝或回落到站内首页，不得跳站外。
- **证据**：请求 URL + 最终落地域名。
- **副作用恢复/留痕**：改参数探测不落库即无残留；涉及本人会话跳转的，验证后回到站内恢复状态。
- **不算缺陷**：参数值被白名单限制为合作域名（须能说明白名单来源）。

### 5. 越权访问（IDOR）

- **许可分级**：L4 越权类，须明确授权且仅限隔离环境；两个账号均须属本人或已获授权。
- **怎么验**：用**自己的两个账号**（A 创建资源，B 登录）访问 A 的资源 ID；再试未登录访问同一 URL。
- **看什么**：均被拒（403/404/跳登录），且不因把 ID 改成相邻值而泄露。
- **证据**：请求、响应码、响应体中是否含他人数据（脱敏）。
- **副作用恢复/留痕**：A 账号自建资源收尾清理并记录；命中疑似泄露即停，只记证据不扩大范围、不下载他人数据。
- **不算缺陷**：资源本就公开（分享链接、公开问卷），须确认产品定义为公开。

### 6. 错误信息与堆栈

- **许可分级**：L4 注入/异常输入类（构造非法参数触发失败），须明确授权且仅限隔离环境。
- **怎么验**：触发可预期的失败（非法参数、不存在的 ID、超大输入）。
- **看什么**：只给用户可理解的提示；不含堆栈、SQL、框架版本、内网路径、服务器 IP。
- **证据**：错误响应体/页面截图。
- **副作用恢复/留痕**：失败探测不落库即无残留；使用的异常输入值登记在证据中以便复核。
- **不算缺陷**：开发环境返回详细错误（须确认非生产域名）。

### 7. 上传与下载

- **许可分级**：L2 可逆写（正常上传自建文件）；改名/超大文件等异常输入探测为 L4 注入类，须明确授权且仅限隔离环境。
- **怎么验**：上传非预期类型（如把 `.html` 改名 `.jpg`）、超大文件、含特殊字符的文件名。
- **看什么**：类型按内容校验而非扩展名；大小受限并有提示；文件名不被直接拼进路径；上传后的访问地址不可遍历目录。
- **证据**：上传结果 + 返回的文件 URL 形态。
- **副作用恢复/留痕**：上传的测试文件（含被拒尝试的落盘物）收尾清理并登记清单；不清理他人或共享目录内容。
- **不算缺陷**：业务明确允许的类型（如允许上传 HTML 用于展示，须有隔离域）。

### 8. CORS 配置

- **许可分级**：L1 只读观察。
- **怎么验**：只读观察跨域请求的响应头（用浏览器正常访问，不构造恶意站点）。
- **看什么**：`Access-Control-Allow-Origin` 不为 `*` 且携带凭证；不反射任意 `Origin`。
- **证据**：响应头原文。
- **副作用恢复/留痕**：无写副作用，留存响应头截图即可。
- **不算缺陷**：完全公开的只读接口（无凭证、无敏感数据）。

### 9. 第三方脚本与完整性

- **许可分级**：L1 只读观察。
- **怎么验**：查看页面引入的外部脚本/样式域名。
- **看什么**：来源可信且数量可控；关键第三方资源有 `integrity`（SRI）或自托管。
- **证据**：脚本 URL 清单。
- **副作用恢复/留痕**：无写副作用，留存清单即可。
- **不算缺陷**：统计/埋点类脚本按行业惯例不设 SRI（须确认域名可信）。

### 10. 敏感数据的落盘与回显

- **许可分级**：L2 可逆写（提交本人自建的表单数据）。
- **怎么验**：提交含手机号/证件/地址的表单后，检查页面回显、URL 参数、`localStorage`/`sessionStorage`、前端日志。
- **看什么**：证件号等强敏感字段脱敏显示；不把敏感值放进 URL 查询串；不在前端存储明文凭证。
- **证据**：存储快照（脱敏）+ URL 形态。
- **副作用恢复/留痕**：提交的测试数据使用虚构值并收尾清理（编辑态删除或走授权恢复路径）；快照一律脱敏留痕。
- **不算缺陷**：用户自己刚输入且仅本人可见的编辑态回显。

### 11. 认证防滥用

- **许可分级**：L3 不可逆写（消耗尝试计数、可能触发锁定），须明确授权且仅限隔离环境。
- **怎么验**：用**自己的账号**连续输错密码 3–5 次（人工受控进行，不自动填密码）；连续请求验证码 2–3 次（间隔正常）。
- **看什么**：有失败计数/锁定/延迟；验证码有频率限制与有效期；错误提示不区分"账号不存在"与"密码错误"。
- **证据**：第 N 次后的响应提示与响应码。
- **副作用恢复/留痕**：登记消耗的尝试次数与触发的锁定时长、解锁方式（等待/管理员解锁）；验证后确认账号状态恢复并记录；不使用他人账号。
- **不算缺陷**：企业内网 SSO 由 IdP 统一限流（须给出 IdP 侧证据）。

### 12. 传输与混合内容

- **许可分级**：L1 只读观察。
- **怎么验**：页面加载后看控制台混合内容告警与地址栏协议。
- **看什么**：全站 HTTPS；无 HTTP 资源；跳转不降级到 HTTP；表单提交目标为 HTTPS。
- **证据**：控制台告警 + 资源 URL。
- **副作用恢复/留痕**：无写副作用，留存告警截图即可。
- **不算缺陷**：本地开发环境的 HTTP 服务。

## 三、结论形态

| 情形 | 写法 |
|---|---|
| 全部可验项已验且通过 | "安全防护：12 项外部可验项已验，未发现缺失；未做渗透与攻击验证，不构成安全结论" |
| 有缺失 | 按项列"缺什么 + 证据 + 影响"，定级不超过 major（真实可利用性需安全团队确认） |
| 缺环境（无第二账号/无 HTTPS 环境/无隔离环境授权） | 逐项记"未验 + 原因"，按 `evidence_grading.md` 记 E3 |
| 疑似但无法确认 | 记"待安全确认"，**不写"存在漏洞"** |

**禁止表述**："通过安全测试""无安全问题""已加固"。可以写"已验N项，未验M项，发现K项防护缺失"。

## 四、纪律（与缺陷判定一致）

1. 只用自己的账号与授权范围；跨账号验证必须两个账号都属本人或已获授权。
2. 不做自动化扫描（目录爆破、注入类自动化尝试、暴力破解），不因"顺手"越界。
3. 命中即停：发现疑似越权/泄露，**记录并上报**，不扩大验证范围、不下载他人数据。
4. 证据脱敏：密钥、令牌、手机号、证件号一律打码，只留可复核的结构。
5. 不把"配置不符合最佳实践"直接等同于缺陷——须说明对应用户影响，否则记建议。
6. 越界动作（超出条目标注许可分级）一律不做：无授权的 L3/L4 条目整条记"未验 + 原因"，不以"已部分执行"冒充"已验"。
