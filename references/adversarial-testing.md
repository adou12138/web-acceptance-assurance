# 对抗性测试编排（双循环）

定位：在契约验证批次之外引入独立挑战批次，用最小对抗执行闭环检验"已通过的结论是否真的站得住"。本文只规定执行编排与纪律；判据登记字段见 `oracle-contract.md`，事件与复核记录见 `finding-triage.md`，断言挑战（隔离源码变异与黑盒注入）的判定纪律与记分口径见 `assertion-challenges.md`。对抗是主流程的增强，不替代契约验证，也不扩大授权范围。

## 双循环执行模型

- **契约验证批次（A 循环）**：按既有规格、cases JSON 与台账执行正式用例，产物走既有门禁，不在本文重复定义。
- **独立挑战批次（B 循环）**：针对 A 循环"已通过/未覆盖"的条目发起对抗探针，每批有独立目标、预算与停止条件。两批交替推进：A 批产生观察与缺口 → B 批挑战当前最可信的结论 → 结论回写台账 → 下一轮 A 批。B 循环不建立第二真相库、不产出平行台账。
- 交替节奏按预算与风险定，不要求固定配比；小任务可以只做一轮 B 批，大任务按高风险面分批。B 批暂停或终止不影响 A 批既有事实，但未关闭的对抗义务按门禁规则压低结论上限（见 `output-templates.md` 的对抗门禁呈现）。

## 挑战来源

1. **未证实假设队列**：规格分析与探索中标记为暂定/待核验的规则与行为假设，优先挑战"看起来最稳"的。
2. **负面断言**：已确认规则中的禁止项与拒绝路径（"必须失败/不得出现/不允许"），逐一验证拒绝确实发生且无副作用。
3. **高风险组合**：风险面登记中风险为 high 的 SURF 条目、成对覆盖未覆盖的多维交互、历史漏测区。

## 探针（probe）

挑战以探针为单位。**探针来源并列，无先后强制**：

- **清单参考**：可查挑刺清单 `probe-playbook.md`（坑点→探针模板 + 通用方法库），作为可选武器库。
- **自主构造**：专家可基于 `ATK-` 攻击假设或现场观察自行设计攻击场景。**清单未覆盖的攻击场景与清单内探针具有同等执行优先级**；清单已覆盖 ≠ 攻击面已覆盖。

无论来源如何，构造前都要补全两段，缺一段不得执行：

- **【输入/扰动】**：具体输入、操作序列、注入故障或时序扰动；写明作用对象与施加方式。
- **【预期依据】**：判定结果的依据，只能来自需求原文、接口契约、明确业务不变量或已确认规则（R-xx）；模型自猜的规则一律先记"待核验"，不得直接当预期执行判定。预期依据没有来源的探针只能产出观察，不能产出 PASS/FAIL。

**ATK 轨道的例外**：攻击假设不强制两段格式——它的 `validation_path` 可以是人工步骤、场景推演或代码走读，`hypothesis` 允许模糊。这是有意的设计差异，不是漏填（判据见 `oracle-contract.md`）。但推演/走读判出的否定不是实测：用推演/代码走读判定「未命中」且影响面属功能/数据/权限时，须证据挂钩（`--replay-note` 点名该 ATK 并引用既有观察，或补一条实操探针）；`verified_by=practical` 的「未命中」须挂可关联的执行记录或落盘证据，不可用解释替代。**「未执行」不受此约束**——允许长期悬置是有意让步。

探针执行结果作为事件记录（EVT-），区分自然失败与人工注入（injected 字段）；候选与正式缺陷的分账、复核状态机按 `finding-triage.md` 执行。**计划外探针（`surfaces_beyond_plan`）计为产出**，不因"不在清单内"而降低记录优先级。

## 单写者纪律

主会话是对抗结论的唯一裁定者与写者：探针结果、候选定性、台账回写统一由主会话完成；挑战批次不另建真相库、不由子代理直接写台账或缺陷。观察采集工具与子代理只提供原始观察与线索，裁定与落账回到主会话。

## 能力探测与预算

进入 B 循环前先做能力探测，再定探针清单：

1. **先查当次真实可用通道**：浏览器拦截/改写能力、脚本执行权限、测试账号与角色、网络观测通道——逐项实测，不沿用历史会话或静态清单的结论。
2. **缺口四分类**：把探测出的缺口归入四类并只阻塞相关条目——
   - **环境**：目标环境/沙箱/时钟/网络不可控；
   - **输入**：测试账号、数据包、文件样例、授权范围不足；
   - **观测**：日志、数据库读回、请求观测通道缺失；
   - **实现**：拦截、注入、时序控制等执行手段不可用。
3. **"暂不支持"与"永久不支持"必须区分**：静态名单（如本包各文档声明的边界）只作提示，**不作永久豁免**；新能力可用后（新账号、新通道、新工具授权）必须重新评估对应缺口并解除相关条目阻塞。写"暂不支持"须附恢复条件；确实无法恢复的才标"不支持"并保留在风险清单。
4. **预算**：B 循环按探针数、时间盒或副作用配额任一口径设预算；**预算耗尽即停机**，停机记录必须写明：已消耗量（探针数/时长/写入次数）、剩余未执行的 ADV 义务清单及影响。停机不改判已执行探针的结论。
5. **配额触发停机**：写入次数、污染数据量或告警达到执行前约定的配额上限时立即停机，先核对副作用（见下节）再决定是否续批。

## 扰动安全与副作用

- **共享资源串行**：多个探针触碰同一共享资源（同一订单、同一配置、同一队列、同一测试账号）时串行执行，不并发注入；前一个未核对副作用前不施加下一个扰动。
- **扰动启停**：每个故障注入/时序扰动必须写明启动条件与停止条件（超时、观察完成、告警触发）；停止后立即核对目标恢复原状，核对不到恢复证据记 side_effect_pending。
- **副作用核对**：扰动结束按执行管理口径核对业务读回与残留；人工注入产生且无法还原的残留进写操作台账，按 `execution-management.md` 的写操作三选一收尾。
- 扰动只施加于已授权的目标与环境；授权外对象、生产数据与真实资金流一律不注入。

## 结论与门禁衔接

**对抗循环是产出技术结论批次的必选项**：每个产出技术结论的批次必须登记 plan 并执行探针，并运行 `scripts/adversarial_gate.py`——门禁**默认启用**，空 plan 且无豁免理由时结论上限压"待核实"（不再放行）；确需关闭用 `--no-enforce` 并给出 `--disable-reason`，关闭状态与理由须在交付物中原样呈现（不得静默关闭），**关闭态的上限为"待核实"**（关闭只解除"对抗循环未启用"的阻断，不放松门禁已算出的更严结论）；纯只读小任务可用 `--waiver` 附理由豁免，豁免留痕但**不上抬结论上限**——verdict_ceiling 最高仍为"待核实"，豁免是否合资格（只读且小任务）由 `execution_ledger._adversarial_precondition` 机械校验，本门禁只留痕并输出 `waiver_granted` 标志。门禁含**抽样复核**：传入 `--scope`（本轮功能面/候选风险面清单，独立于 plan 台账）时从中抽 N 项（默认 2，`--sample-size` 可调）检查是否已登记为 SURF——抽中未登记且无豁免说明（`--exemptions`）时压"待核实"；豁免只解除该项阻断，不上抬其它规则已压低的上限；未提供清单时记"未执行抽样复核"，**不得显示为"抽样通过"**。抽样按清单内容派生的确定性种子执行，同一组功能面无论清单如何排列都抽到同一批，抽样位置分布均匀（不使用低阶位周期短的线性同余洗牌——那会让某些位置几乎抽不到）。B 循环不单独出"通过/不通过"结论；其事实（探针数、有效缺陷、误报、未裁定、风险覆盖）经该脚本计算补充上限，与探索 gate 一并约束最终结论。报告呈现规则见 `output-templates.md`；候选复核与聚类最小化规则见 `finding-triage.md`。

**入口 A 的攻击假设（ATK）**：攻击假设是**独立于 plan 的登记条目**，走自己的校验轨道（`scripts/attack_coverage.py --atk`），不拆成单条可证伪预测，允许长期悬置；具体字段与判据见 `oracle-contract.md` 的「ATK（攻击假设条目）」。
