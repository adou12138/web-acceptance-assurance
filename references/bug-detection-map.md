# 检出维度总图（bug-detection-map）

> **衍生对照物声明**：本图是三套冻结维度体系（requirement-review 评审 8 维 / figma-ui-parity 4.47.0 的 45 维 7.x / api-test 5.0.2 的 31 大类 A–L·AA–AE）与专家主体五视角的**交叉索引**，不是第四套事实源，也不替代任何一套门禁。三源升级时须按 `docs/SYNC-NOTES.md` 三张对照表**同步对照本图**（双维护纪律）。三套命名空间**彼此独立**（figma 7.x / api 字母大类 / 评审维度名），跨 skill 报告引用维度时必须带 skill 名，禁止裸编号。

## 一、用途

1. **路由**：判断一次任务应该进哪个 skill（按线索：设计稿→figma；契约→api-test；纯需求→评审→生成→主体执行）。
2. **互补**：确认三套维度**并集**覆盖了“需求 bug 检出面”，并显式标出重叠区（允许重叠，但结论口径各自独立）。
3. **升级**：主体走查发现深度信号时，按 §四升级映射启用 figma 页面侧深查（见 agents「专家主动升级」）。

**业务模块坑点**：按登录/权限/表单/上传/支付/导入导出/异步回调/接口/兼容/弱网/安全基线/无障碍/国际化/时区/AI 逐模块排查见 `references/business-pitfalls.md`（与按症状分类的缺陷模式互补）。

**判定与误报**：维度只回答"该往哪看"，不回答"是不是缺陷"。判定链与证据最小集见 `skills/case-generator/references/methodology/detection_methods.md`；模式触发见 `defect_patterns.md`；误报降级与三类分账见 `false_positive_guard.md`。

## 四、主体走查 → figma 深查的升级映射（专家主动升级）

主体五视角走查命中以下**可判定信号**时，应当升级 figma 页面侧链路（读 figma SKILL.md R0/R1；安全策略按整合后默认档位 `safe`，写操作仍须必问矩阵确认）：

| 主体走查信号 | 升级到 figma 维度 | 深查内容 |
|---|---|---|
| 键盘走不通 / Tab 顺序异常 | **7.43** | 键盘焦点顺序与逃逸（keyboard_order.js） |
| 疑似对比度不足 / 依赖色觉区分 | **7.41 + 7.42** | WCAG 子集审计 + 设计侧文本对比度对照 |
| 焦点不可见 / 弹层焦点逃逸 | **7.43** | 焦点可见性与顺序 |
| CLS 异常 / 长任务 / 首屏资源过重 | **7.40** | TTFB/FCP/LCP/CLS/TBT/资源体积 |
| 点击后首响慢（≥2000ms 口径） | **7.44** | 交互首响应时延 |
| 断点溢出 / 多视口错位 | **7.4** | 响应式实测 + constraints 断言 |
| 点击后无反馈 / 死按钮（合法禁用除外） | **7.17 + 7.22** | 按钮审计 + 交互期失败：核对点击是否有可观察状态变化或错误提示 |
| 提交/操作后状态残留、返回刷新后数据不一致 | **7.21** | 状态旅程与读回：核对成功 toast 之外的业务落库结果 |
| 控制台异常 / 请求 5xx / 断网 | **7.33 + 7.36** | 网络与运行期失败矩阵：记录失败时的页面表现与恢复 |
| 长文本/空态/未渲染变量（如 `{{name}}`、`null`） | **7.23 + 7.8** | 双向盘点 + 文案比对：长内容溢出、空态引导、模板变量是否渲染 |

安全与无障碍的**外部可验**深查不走 figma 维度：安全防护 12 项（响应头/Cookie/越权/上传/限流等）见 `references/security-verification.md`，无障碍人工审计（37 条 A/AA + 键盘 12 步 + 读屏脚本）见 `references/a11y-audit.md`。

升级动作：报告标注"升级理由 + 起始主体信号 + 六态口径"；**未命中信号即不升级**（防随意扩大范围），但上述信号一旦出现应主动升级而非等用户报告。反向（figma 走查发现需求级缺陷线索）→ 回评审/主体台账登记。

**正常/异常交替纪律**：按页面×任务×角色×状态×数据×设备候选集组织，正常旅程与异常/权限/网络失败旅程交替推进，不先写完全部用例才开始执行；高风险交互（写操作、权限、支付/删除类）单列并先确认授权。

## 五、边界声明

1. 三套门禁**互不套用**（api-test 与 figma 均为自治质量体系，见各自 SKILL.md 砺衡段）。
2. 报告**文件不合并**：主体 HTML+CSV 为总报告载体；api-test/figma 报告按附件引用，但 figma 升级结果须按状态映射回写探索清单后才计入技术结论（见 agents「升级后的回写契约」）。
3. 本图不承载任何判定逻辑；与 references 正文冲突时以各权威文件为准。
4. **状态映射（唯一口径）**：figma `pass→PASS`、`fail→FAIL`、`warn→PASS`、`pending/notRun/dataMissing→BLOCKED`。映射后条目的 `observation` 前缀 `source=figma-ui-parity:7.xx`，证据指向 figma 报告；探索门禁只按 PASS/FAIL 计覆盖，SKIPPED/BLOCKED 只在 `skipped_views` 留痕。
   **六态保真纪律（v3 G15）**：映射只用于探索门禁的覆盖计数，**不得改写外部报告的原状态**；`warn` 不得以"业务 PASS"结论覆盖，须在 observation/报告同时保留 `warn` 原文与严重性；`pending/notRun/dataMissing` 不得因同视角存在另一条 PASS 而消失，须作为该视角的未验证缺口保留（必选性单独标注）。必选质量属性（security/compatibility/content）被阻塞或未执行时，结论上限依 `exploration_state` 的 `blocked_mandatory` 判定，不因同视角其他 PASS 放行。
5. **缺陷编号命名空间**：主体台账 `BUG-`、接口专项 `API-`、figma `FIG-`；跨来源引用写“来源前缀+原编号”，台账用 `source`/`external_id` 关联，禁止裸编号互引。
