## 二、本次落地条目

### N3 变更日志括注与基线数字修正（文档）

- **改动**：
  - 括注改为「（v1.44.2 为 630 总：628 passed + 2 环境跳过，226 子测试）」；注明 `test_skill_registration` 的 2 项本机路径检查随运行环境跳过/通过，计数以实际环境为准。
  - 头数字改为「735 passed, 2 skipped（环境依赖）, 230 subtests passed」，不再把跳过计入 passed。
  - 分批算术链保留：630+19+25+20+12+19+12=737（总选用例数），passed 与 skipped 分账书写。
- **实测依据**：v1.44.2 工作树 630 总（627 passed + 2 skipped + 1 个同环境 N12 失败）+ 226 subtests；当前库 737 总 = 735 passed + 2 skipped + 0 failed（N12 修复后）。

### N12 Python 3.9 环境兼容修复（代码，方案外新增）

- **落点**：`scripts/case_data.py:472`。
- **改动**：`Path.write_text(..., newline="\n")` 改为 `Path.open("w", encoding="utf-8", newline="\n")` 后 `yaml.dump` 写入；`execution_ledger.py` 两处 `open(..., newline=)` 已兼容，不动。
- **验收**：Python 3.9 下 `to-yaml` CLI 返回码 0；既有 `test_case_data` CLI 链全绿。

### N4 ATK 零登记解释检查（代码）

- **落点**：`scripts/attack_coverage.py` `analyse()` 的 `atk_entries is None` 分支与 CLI。
- **改动**：
  - 新增入参 `atk_absent_reason`，CLI 对应 `--atk-absent-reason`。
  - 未提交 `--atk` 且理由为空 → gap `atk_absent_unexplained`（压上限）；有非空理由 → notice 披露原文。
  - **罚不解释，不罚零登记**：提交了 ATK 时本项完全不触发；理由只是说明本轮为何前置攻击假设为空，不要求凑条目数。
- **验收三向**：无 ATK 无解释被拦；无 ATK 有解释放行；有 ATK 不受影响。

### N5 假设锐度质检（代码）

- **落点**：`scripts/attack_coverage.py` 假设处理段；词表复用 `scripts/case_data.py`（`PLACEHOLDERS`/`has_placeholder`/`is_noncommittal`，函数内懒加载，与 `execution_ledger` 既有同源加载方式一致）。
- **合格信号（满足其一即放行，正则从宽）**：
  1. 数值/长度（`\d`、字符/字数/KB/MB 等）；
  2. 角色名/状态名（角色、管理员、租户、未登录、锁定、待审核等）；
  3. 条件组合（并发、同时、重复、连续、交叉、多次、组合）；
  4. **对象 + 预期方向词**（拒绝/拦截/失败/消失/保留/一致/报错/提示/回滚/禁止/限制/为空/越权等）——v3 补充通道，防误杀合法自然语言假设。
- **不合格处置**：命中占位词表或纯非承诺空话，且无任一合格信号 → gap `hypothesis_vague`；该条不计入 `supported`，但保留在台账披露，不删除记录。
- **不罚诚实自检**：「并发建卷时卷名重复应拒绝」「删除后条目应消失」「越界输入应被拒绝」必须放行；「如果输入超长则保存会坏」（无具体取值/对象）被拦。误判案例回填测试集后再收紧阈值。
- **验收双向**：浅而广的空话假设被拦且不计覆盖；锐利假设放行。

### N6 「解释或复打」义务（代码，政策反转）

- **落点**：`scripts/attack_coverage.py` `single_method_high_risk` 分支；CLI 新增 `--replay-note`。
- **触发条件（全部满足）**：高风险面记录 ≥3、仅 1 种方法、`supported` 结果全部 held（无 broken）。
- **义务二选一**：追加一条不同方法的探针（记录 hypothesis + 结果），或提交 `--replay-note`（须点名 `surf_id` 并给出不复打理由，引用既有观察编号）；两者皆无 → gap `surface_unreplayed_unexplained`。
- **边界**：已 broken 的面不触发；这不是方法多样性配额（不要求凑够 N 种方法），只是「建议」升级为「须回应」。
- **政策反转披露**：既有口径「单一方法只提示不压上限」被本项替代；`retest_suggestions` 保留作为动作建议。
- **验收双向**：浅而广且无解释被拦；附锚定解释放行；换方法复打后放行；broken 面不触发。

### N7 「通过」前强制结构化残余声明（代码）

- **落点**：`scripts/attack_coverage.py` residual 判定段。
- **改动**：无其他 gaps（结论将达「通过」）时，残余声明必须为结构化声明（`mode=structured`，逐条对账已实现）；仅自由文本 → gap `residual_declaration_required_for_pass`。「待核实」档保留文本入口，不抬高诚实登记成本。
- **验收**：文本 anchored 声明在通过档被拦、在待核实档放行；结构化声明不符仍被既有能力拦住（回归）。

### N8 只读修订 × 写台账交叉核对（代码 + 文档）

- **落点**：`scripts/execution_ledger.py` `summarize()`/`_final_precondition()`；`scripts/amendment_class.py` 字段约定；`references/phase-workflow.md` 2.3 节同步。
- **改动**：
  1. `readonly_lead` 修订记录新增可选 `linked_records`（关联台账/写操作条目 ID 列表）。
  2. `summarize()` 新增可选输入 `write_ops_ledger`（figma `write_ops_ledger.py` 产物）；CLI `summary` 加 `--write-ops-ledger`。
  3. 收尾复核：仅对**显式提供了 `linked_records`** 的 `approved_readonly` 修订，核对关联条目在写台账中无 `caution`/`danger` 写记录；发现不符 → 过程问题登记 + 结论压「待核实」+ 首屏披露「只读申报与写记录不符」。
  4. **默认不压档**：写台账文件未提供、或修订未显式关联条目 → 只披露「未做机械对账」，不压上限。时间窗兜底关联仅作为披露线索，不做压档依据。
- **验收三向**：只读申报 + 纯读记录放行；只读申报 + 关联到写记录被拦并披露；`scope_change` 已批 + 写记录放行；缺台账/缺关联只披露。
