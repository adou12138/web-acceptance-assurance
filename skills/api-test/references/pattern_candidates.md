# 缺陷模式候选池

> 候选只作为待评审素材，不自动并入正式缺陷模式清单。
> **纪律**：候选先进本池，评审通过后才并入 `defect_patterns.md`（正式清单）。并入时看该模式是否已有检测通道：没有则同步到 `pattern_engine.py` 加一条 `match` + `gen` 规则；若已由安全载荷清单（G 族）、组合生成器（B-COMBO）等既有通道兑现，则只入清单、不加引擎规则——同一条检查由两个通道各生成一遍用例是重复覆盖，不是加强。每条候选必须带证据（缺陷现象 + 触发用例来源），无证据的候选不得并入。

## 登记方式（`scripts/pattern_feedback.py`）

闭环的最后一环：把本轮新发现、现有模式清单没覆盖的缺陷抽象成候选，回流待评审。同一批次从 CSV 挖掘时，按维度 + 现象归一化前 50 字聚合计数：去方括号内容、数字归一为 N、去空白及指定标点。持久去重是另一口径：按现象单元格前 60 字精确比较（先去首尾空白、将管道符替换为 `/`，截断后去首尾空白），不按维度或归一化前 50 字合并。跨批次已登记的候选直接跳过（不重复登记，次数也不累加），不重写历史记录；已被正式清单覆盖的现象不再登记。

```bash
# 从问题台账自动提炼候选（按行提炼「缺陷」类条目，聚合去重后登记）
python scripts/pattern_feedback.py --from-csv api_test_issues.csv

# 手工登记一条（--add 必须同时给出 --dim 与 --symptom）
python scripts/pattern_feedback.py --add --dim B8 --symptom "可选字段传空被拒" --evidence "用例 B-NULL-xx"
```

| 参数 | 说明 |
|---|---|
| `--from-csv` | 从问题台账 CSV 自动提炼候选（读 16 列台账的「类型/维度/问题描述/编号」列，只取「缺陷」类，按维度+归一化现象聚合） |
| `--add` | 手工登记一条候选；未同时提供 `--dim` 与 `--symptom` 时报错退出 |
| `--dim` | 候选所属维度编号（如 `B8` / `H6`） |
| `--symptom` | 缺陷现象，用现象口吻描述（如"可选字段传空被拒"） |
| `--evidence` | 证据 / 触发用例来源；`--add` 时省略则记「人工登记」 |

`--from-csv` 与 `--add` 必须给其一，都不传时直接报错退出（`需指定 --from-csv 或 --add`）。本脚本**只写候选池**，不改 `defect_patterns.md`、不改 `pattern_engine.py` 规则；已被正式清单覆盖的现象会自动跳过，不重复登记。覆盖判断先剥离现象开头的 `[用例ID]`，再将现象正文与正式模式名（Top 标题及补充模式表格首列）按归一化前 6 字作前缀比较；不足 6 字时按较短的非空前缀匹配，非模式小节标题不参与。

## 候选数据在哪

候选行是**运行时数据**，写在 `references/pattern_candidates.log.md`（已在 `.gitignore`，不入库）——每跑一次 `--from-csv` / `--add` 就追加一批。本文件只保留纪律与登记口径，所以能稳定入库、长期不变。

评审流程：读 log 里的候选 → 评审 → 通过则并入 `references/defect_patterns.md`（并按开头那段纪律判断要不要同步加 `pattern_engine.py` 规则）→ 在 log 里把该行评审状态改成「已并入 / 已归并 / 不通过」。log 丢失不影响正确性（它只是待评审素材），但会丢掉「哪些候选已经评审过」的记忆。

表列含义：登记时间 / 维度 / 候选模式（现象，取前 60 字、管道符替换为 `/`）/ 出现次数 / 证据或触发用例 / 评审状态（`待评审`、`已并入`、`已归并`、`不通过`，机械统计按状态前缀归组）。
