# 接口测试标准

> 供 P2「测试点草稿」阶段使用：接口类需求生成测试点时的必查维度。
>
> **出处**：本文档内容改编自开源项目 [Kokxi/qa-testcase-generator](https://github.com/Kokxi/qa-testcase-generator) 的 `references/quality.md`（MIT License），并结合接口测试通用实践补充。

---

## 1. 参数校验

| 维度 | 检查点 |
|------|--------|
| 必填参数 | 缺失必填参数 → 返回明确错误码与提示 |
| 参数类型 | 传错类型（字符串传数字、数字传布尔） → 拒绝 |
| 参数长度 | 超长、超短、边界值 |
| 参数格式 | 日期、邮箱、手机号、枚举值 |
| 多余参数 | 传入未定义字段 → 忽略或拒绝（按契约） |
| 空值/Null | 显式传 null 与不传的区别 |
| 特殊字符 | 引号、反斜杠、SQL 注入、XSS 载荷 |

---

## 2. 错误码与响应

- 每个错误场景必须断言**具体错误码**，不能只断言"返回错误"
- 错误响应体结构完整（code / message / data）
- HTTP 状态码与业务错误码一致（如 400 vs 500 的区分）
- 错误信息不泄露内部实现（堆栈、SQL、文件路径）

---

## 3. 鉴权与权限

- 无 Token / 无效 Token / 过期 Token
- 签名错误、时间戳过期、重放攻击
- 越权访问他人资源（水平越权）
- 低权限角色调用高权限接口（垂直越权）
- 白名单 / IP 限制

---

## 4. 幂等与并发

- 重复提交同一请求（幂等键相同）→ 只生效一次
- 并发调用同一资源 → 数据不重复、不丢失
- 乐观锁 / 版本号冲突处理
- 分布式锁超时与重试

---

## 5. 限流与降级

- 超过 QPS 限制 → 返回限流错误码
- 熔断触发后的降级响应
- 大流量下的响应时间劣化边界

---

## 6. 数据一致性

- 写入后立即读取（主从延迟场景）
- 事务回滚后数据状态
- 关联资源被删除后的引用处理
- 批量操作的原子性（部分成功 / 全部回滚）

---

## 7. 接口用例结构建议

一条接口用例应包含：

1. 请求方法 + 路径
2. 请求头（认证、Content-Type）
3. 请求参数（完整 JSON 或表单）
4. 预期 HTTP 状态码
5. 预期业务错误码（成功时为 0 或约定成功码）
6. 预期响应体关键字段断言
7. 数据清理动作（如产生副作用）
