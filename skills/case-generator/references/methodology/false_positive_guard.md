# 误报防线：合法近似反例怎么判

> 用途：把"看起来像缺陷、实际不是"的情况挡在缺陷单之外，同时不把真缺陷顺手放过。
> 盲测 `legit_near_misses` 的 `category` 与本文件类别一一对应；误报率按类别统计，才能看出"总把哪一类当缺陷"。

---

## 1. 误报判别四问（缺一就降级）

| 问 | 是 | 否 |
|---|---|---|
| ① 有明文规则或可推导 oracle 吗？ | 继续 | 只能记**建议/待确认**，不得记缺陷 |
| ② 与同类实现/历史行为不一致吗？ | 继续 | 可能只是本页设计，记建议 |
| ③ 能描述用户影响吗（谁、什么场景、多严重）？ | 继续 | 记观察，不记缺陷 |
| ④ 能给出可复核证据并稳定复现吗？ | 记缺陷 | 记**待确认**，写清缺什么 |

四问全过才是缺陷；只过 1–2 问的写进"建议"或"待确认"，并在报告分账。

## 2. 八类合法近似反例

| 类别 `category` | 典型形态 | 为什么不算缺陷 | 应记什么 |
|---|---|---|---|
| `copy_preference` 文案偏好 | "请输入名称" vs "名称不能为空"；标点/语气差异 | 语义正确且不影响操作 | 建议（术语表有冲突才升级） |
| `legit_disabled` 合理禁用 | 加载中按钮置灰；无权限时提交禁用 | 防重复提交/权限约束的正常实现 | PASS（记录状态即可） |
| `decorative_image` 装饰图 | 纯装饰插图无 alt | 非信息载体，读屏无需朗读 | PASS（信息图无 alt 才是缺陷） |
| `permission_hidden` 权限隐藏 | 访客看不到"提交"入口 | 按角色隐藏是正确行为 | PASS（可点且生效才是越权） |
| `viewport_not_kernel` 视口≠内核 | 仅缩放视口，未在第二内核实跑 | 模拟不能代表内核差异 | 待确认（缺真实内核环境） |
| `design_missing` 无设计基线 | 无设计稿时判间距/字号"不符" | 无对照物，无法判定 | 待确认（列未评审项） |
| `third_party_limit` 第三方限制 | 浏览器禁用剪贴板、支付沙箱限制 | 平台策略，非产品缺陷 | PASS/建议（需有提示） |
| `out_of_scope` 超出承诺范围 | 需求未承诺暗色/移动端/i18n | 未承诺不等于缺陷 | 建议或范围缺口 |

## 3. 容易反向出错的三种情况

1. **把"合法隐藏"当越权**：入口不可见 ≠ 越权。必须验证"低权账号能通过接口/URL 执行"才算。
2. **把"视口模拟"当兼容结论**：缩小窗口出现错位只能记 UI 问题（若影响当前视口），不能推断 Firefox/WebKit 也坏；反之，视口正常也不能宣称跨内核通过。
3. **把"文案偏好"当缺陷**：先查术语表/同类文案；有明确术语表且实现违背，才升级为缺陷（客观错误），否则记建议。

## 4. 分账口径

| 类别 | 进缺陷单 | 进报告 | 影响验收 |
|---|---|---|---|
| 缺陷（四问全过） | 是 | 缺陷清单 + 证据 | 是（按严重性） |
| 待确认（缺 oracle/证据/环境） | 否 | 未确认项 + 缺什么 | 是（列未测义务，压低结论上限） |
| 建议（偏好/优化） | 否 | 建议清单（不计缺陷率） | 否 |

报告里三者**分列**，不得把建议算进缺陷数，也不得用"建议"掩盖待确认。

## 5. 盲测里的用法

- 答案键的 `legit_near_misses[].category` 取上表 8 个值；
- 执行方的 finding 命中某类近似反例 → 记一次误报，按类别累计；
- 某类误报 ≥ 2 次，说明该类判据需要补进 `detection_methods.md` 或 `defect_patterns.md`，而不是简单"下次注意"；
- 合法反例被记成缺陷，与真缺陷漏检同等扣分——两者都说明"判据不准"。
