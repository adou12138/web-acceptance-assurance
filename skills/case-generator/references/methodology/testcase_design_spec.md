# 测试用例设计规范

> 供 P6「用例展开生成」阶段使用：用例结构、质量底线与输出规范。
>
> **出处**：本文档内容改编自开源项目 [Kokxi/qa-testcase-generator](https://github.com/Kokxi/qa-testcase-generator) 的 `references/templates.md` 与 `references/quality.md`（MIT License）。

---

## 1. 用例结构模板

```yaml
用例编号: TC-NNN
业务域: 业务域名称
优先级: P0|P1|P2|P3
测试维度: 功能|可靠性|效率|安全性|易用性|可维护性|兼容性
用例类型: 冒烟测试|回归测试|探索性测试|验收测试
设计方法: 边界分析+等价类|状态迁移|判定表|场景法|Pairwise
测试场景: 测试场景描述
测试点: 具体验证点
操作步骤:
  - 步骤: 1
    操作: 操作描述
    预期: 预期结果
测试数据: 测试数据说明
前置条件: 执行前环境或数据准备
需求来源: 需求来源引用
标签: [设计方法, 流程类型, 优先级]
```

> 说明：`预期` 字段嵌在 `操作步骤` 数组内部（非顶层字段）。输出 Excel 时会提取 `操作步骤[].预期` 单独渲染为「预期结果」列。

---

## 2. 优先级定义

| 优先级 | 含义 | 分配规则 | 建议占比 |
|--------|------|----------|----------|
| P0 | 冒烟级 | 核心层主流程 + 阻塞性异常 | 10-15% |
| P1 | 核心级 | 核心层分支 + 重要层主流程 + 关键边界 | 30-40% |
| P2 | 一般级 | 核心层非关键 + 重要层异常 + 辅助层 | 30-40% |
| P3 | 低优先级 | 极端边界 + 低频场景 + 探索性 | 10-20% |

---

## 3. 用例质量标准

| 维度 | 要求 | 不合格示例 |
|------|------|------------|
| 步骤数 | 每条用例 3-5 步 | 只有 1 步「验证登录功能」 |
| 操作描述 | 具体可执行 | 「执行操作」「进行验证」 |
| 预期结果 | 明确可验证 | 「成功」「正常」 |
| 测试数据 | 提供具体数据 | 「测试数据」四个字 |
| 需求追溯 | 关联需求 ID | 无需求来源 |
| 步骤-预期对应 | 每步操作都有对应预期，数量一致 | 5 步但只有 3 条预期 |

## 4. 测试数据生成规则

按以下优先级生成具体值：

1. **边界值数据** — 自动推导最小/最大值的具体数字
   - 示例：密码 8-20 位 → 8 位、20 位各一条
2. **有效等价类数据** — 合规范围内的典型值
   - 示例：8 位含大小写字母 + 数字
3. **无效等价类数据** — 每个违规类型各一条
   - 示例：全小写、无数字、超短
4. **特殊值数据** — 空值、null、0、空格、Unicode 字符

> 涉及真实数据的用例，统一使用测试专用假数据，并标注「测试数据」前缀。

## 5. 四层覆盖深度检查

设计用例的目标不是「覆盖需求文字」，而是**发现问题和隐患**。按顺序逐层走完，不允许跳层：

```
第一层 主流程走得通
  ↓
第二层 流程各环节的页面元素/交互/数据/状态都测了
  ↓
第三层 每类黑盒方法至少用了一次
  ↓
第四层 至少想了 3 个「什么情况下会出问题」的场景
```

| 层级 | 完成标志 | 常见遗漏 |
|------|---------|---------|
| 第一层：主流程 | 核心业务路径正向走通 | 只测页面加载，没测完整「进入→操作→退出」链条 |
| 第二层：业务分层 | 每个 UI 元素 + 字段值边界 + 元素间组合都验证 | 只单独测搜索/筛选/排序，漏组合使用；字段只测「有值」，没测 0/空/特殊格式 |
| 第三层：黑盒方法 | 场景法/边界分析/等价类/判定表/状态迁移各至少覆盖一种 | 只做正向+负向，没做隐式功能推测（分页器、搜索防抖、空状态提示） |
| 第四层：探索性 | 边界数据/特殊操作/环境异常/数据一致/隐式推测各至少一类 | 只覆盖零数据和特殊字符，漏空状态 UI、兼容性、翻页行为 |

> 不是用例越多越好，是每一层都走到了才停。某一层想不出用例，说明需求理解不够深，应回读需求。

---

## 6. 覆盖度指标

| 指标 | 要求 |
|------|------|
| 需求覆盖率 | ≥ 100%（每个需求至少 1 条用例） |
| 测试维度覆盖 | ≥ 3 种（功能 + 安全/可靠性/性能中至少 2 种） |
| 设计方法覆盖 | ≥ 3 种（场景法 + 边界分析 + 状态迁移/判定表） |
| 业务域覆盖 | 100%（每个业务域都有用例） |

---

## 7. 输出前验证清单

- [ ] 用例编号连续、无重复
- [ ] 所有必填字段齐全
- [ ] 操作步骤具体可执行，3-5 步
- [ ] 预期结果明确可验证，无「成功/正常/符合预期」等模糊词
- [ ] 步骤数与预期数一一对应
- [ ] 测试数据为具体值
- [ ] 优先级分布合理（P0 占 10-15%，P1+P2 占 60-80%，P3 占 10-20%）
- [ ] 冒烟用例聚焦「入口可达 + 核心展示」，不标注异常/删除类
- [ ] 每个业务域至少覆盖输入 + 流程 + 权限三类异常
- [ ] 每个业务域至少使用 3 种不同设计方法
